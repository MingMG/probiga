## 1. 最终结论

本轮要求内能够通过代码、迁移和生产操作完成的项目已经完成并部署。V2 的数据门禁、策略信号、四仓竞争、主题集中度、动态持仓、加仓、模拟订单、逐笔账本、对账、异步回测、API 和调度链已经接通。

验收结论分为两层：

| 层级 | 结论 | 说明 |
|---|---|---|
| 代码与生产机械链 | 通过 | 迁移、服务、决策、Worker、逐笔回测、对账、API、幂等和安全阻断均按设计运行 |
| 策略晋级与新开仓 | 不通过 | 当前策略未通过完整样本外和基线比较，实际券商费用、账户权限、QMT Level-1 连续性及日 K 来源补证仍缺证据 |
| 真实交易 | 不在本期，保持关闭 | `real_trading_enabled = 0`，生产真实委托为 0 |

生产当前状态：


这不是“系统不能用”。研究、历史回放、门禁判断、模拟账本和验收链已经可用；系统现在拒绝把尚未证明的策略和不完整的券商配置伪装成可买信号。

## 2. 本轮完成的改造

### 2.1 数据库与版本链

- 生产共有 28 张 V2 业务表，迁移 `001` 至 `005` 均已应用且校验和固定。
- 迁移 `005_trading_v2_theme_risk_chain` 为信号、交易意图和持仓批次增加 `theme_code`，并建立账户主题持仓索引。
- 迁移前结构快照：
  `/opt/ProBigA/data/backups/trading_v2_schema_20260726_003311.json`
- 修复迁移干跑误报：`--dry-run` 现在会读取迁移记录，生产复核准确显示 `001` 至 `005` 全部为 `exists`。
- 回测请求哈希现在包含研究协议版本、代码源指纹、策略配置哈希和请求参数。
- ETF 数据快照哈希现在覆盖实际使用的 23,675 行数据版本，而不是只哈希日期摘要。

### 2.2 动态持仓与灵活买卖

- 趋势、策略失效或高风险事件出现时可立即进入退出链，不再按固定持有天数死拿。
- `BROKEN`、`RISK_EXIT`、`EXIT_PENDING_T1` 和 `EXIT_PENDING_LIQUIDITY` 属于不可逆退出承诺；等待 T+1 或流动性恢复时不会被普通上涨信号重新改回持有。
- 保护位只能上移，不能下移。
- 强势、已有浮盈且风险预算允许时可继续持有。
- 加仓不再是占位逻辑：会重新读取账户现金、持仓估值、主题暴露、费用、证券规则和组合风险，再生成不可变 `ADD` 意图、风险裁决和模拟买单。
- 加仓风险使用已经上移的保护位，不再错误回退到最初止损。
- 亏损补仓、超过四仓、主题超限、费用或规则未知、数据阻断时均拒绝加仓。

### 2.3 费用、规则和模拟执行

- 费用引擎支持买卖费率、最低费用、固定费用和按股费用。
- 部分成交只在订单累计层面收取一次最低费用，避免每个分片重复收费。
- 账户只能绑定指定版本的证券规则和费用版本，不能自动选择“最新但未确认”的规则。
- 费用和权限配置采用新版本记录，不修改已经发布的旧规则。
- 未提供国金实际费用证据时，研究可以使用明确标记的假设费用，但策略不能晋级。

### 2.4 对账

- 修复“开户前日期对账导致当前账户被误冻结”的生产问题。
- 开户前日期生成不可变的 `SKIPPED_BEFORE_ACCOUNT_OPEN` 记录，不修改当前账户。
- 对账增加现金事件链、未来事件、订单、成交幂等、持仓批次和账户余额检查。
- 有持仓时会使用对应交易日、指定 QMT 来源、带数据版本且质量合格的收盘价计算市值和权益。
- 缺价格、来源不符、无数据版本或质量不合格时阻断，禁止静默使用其他公网价格代替。

### 2.5 回测研究协议 V3

- 次日开盘执行，禁止当日收盘看见信号后按同一收盘价成交。
- 20 万元账户、100 股整手、最低费用、滑点、冲击、涨跌停和成交额容量限制。
- FIFO 逐笔配对并落库买入金额、卖出金额、双边费用、初始风险和净利润。
- 动态退出后不是机械空仓到下个月：冷却 3 个交易日后，若 20 日均线和 20 日收益重新确认趋势，可在下一交易日开盘重新进入。
- 费用和滑点 2 倍、容量减半、次日开盘额外不利跳空、移除最佳交易、移除最大贡献证券、9 点参数邻域和 2,000 路移动区块自助检验。
- 完整保存动态方案和“不加快速止损层”基线的收益、回撤及逐笔指标。
- 已经看过的历史区间不会重新标记为“全新盲测样本”。

## 4. 回测结果和人话解释

### 4.1 动态方案

回测交易区间为 2021-01-04 至 2026-07-24：

| 指标 | 结果 |
|---|---:|
| 账户总收益 | 42.52% |
| 年化收益 | 6.86% |
| 最大回撤 | 7.93% |
| Sharpe | 0.840 |
| 完成交易 | 353 笔 |
| 逐笔已实现净利润合计 | 88,744.52 元 |
| 胜率 | 61.19% |
| Profit Factor（总盈利/总亏损） | 1.840 |
| 平均盈利/平均亏损 | 1.167 |
| 单笔平均净利润 | 251.40 元 |
| 动态风险退出 / 恢复进入 | 46 / 7 |

人话结论：这套方案历史上总体赚钱、回撤不大、胜率也不低；但是平均赚一笔只相当于平均亏一笔的 1.167 倍，没有达到需求中 1.50 的严格门槛。

账户总收益与“已闭环逐笔净利润”不是同一个数。前者包含每日权益和期末未闭合仓位的市值变化，后者只统计已经 FIFO 完成买卖闭环的交易。

### 4.2 与不加快速止损层的同口径基线比较

| 指标 | 动态退出并允许恢复 | 不加快速止损层 |
|---|---:|---:|
| 总收益 | 42.52% | 65.13% |
| 年化收益 | 6.86% | 9.85% |
| 最大回撤 | 7.93% | 10.32% |
| Sharpe | 0.840 | 1.072 |
| 风险调整收益 | 5.362 | 6.312 |
| 完成交易 | 353 | 220 |
| Profit Factor | 1.840 | 2.761 |

动态层确实把最大回撤从 10.32% 降到了 7.93%，但代价是增加交易并损失了较多收益，最终风险调整收益反而低于基线。因此不能说它已经是最优解。

这也说明“趋势一破就跑”本身不等于更赚钱。合理做法是保留快速风控能力，但在后续全新前向样本中验证触发强度，不能为了让历史数字好看继续在同一段历史上反复调参。

### 4.3 稳健性

| 检查 | 结果 |
|---|---:|
| 9 点参数邻域为正 | 9/9 |
| 费用与滑点 2 倍后的净利润 | 78,957.17 元 |
| 移除最佳 3 笔后的净利润 | 56,729.23 元 |
| 移除最佳 5 笔后的净利润 | 43,290.31 元 |
| 移除最大贡献证券后的净利润 | 41,732.42 元 |

| 2,000 路区块自助检验总收益为正概率 | 97.8% |

这些结果说明历史利润不是只靠一笔交易、一个品种或一个参数点支撑，但它们仍然不能替代真正的样本外和未来实盘模拟。

### 4.4 未通过的研究门槛

1. 平均盈利/平均亏损为 1.167，低于 1.50。
2. 动态层风险调整收益低于同口径无快速止损基线。
3. 国金实际费用尚未确认，目前只能标记为研究假设。
4. 现有历史区间已经参与开发和检查，不能再冒充全新冻结盲测集。

因此生产回测的 `gate_status = BLOCK` 是正确结果。

### 5.2 调度

### 5.3 故障演练

安全生产演练通过：

- QMT 终端不可用；
- Worker 重启；
- 调度重复触发；
- 配置哈希变化；
- 数据哈希变化。

未在生产主动执行会造成真实中断或资源风险的破坏性演练：

- Windows 采集器强制停止；
- SSH 隧道强制停止；
- 数据库不可用；
- API 强制重启；
- 磁盘空间耗尽。

这些项目必须在维护窗口或隔离环境执行，不能把“为了验收而主动破坏生产”当成普通测试。

## 10. 最终判断

本次不再存在“明知有代码缺口却声称全部完成”的情况。代码可解决项已经完成并在生产复验；目前剩余项都能明确归入以下三类：

1. 必须由用户或券商提供的真实账户事实；
2. 必须由 QMT 恢复和真实交易日产生的数据证据；
3. 必须由未来 40 至 80 个交易日自然积累的前向记录。

在这些事实到位前，系统继续允许研究和验收，但禁止新开仓、加仓和真实交易。
