# Complete analysis snapshot storage

Windows produces the preliminary upper-limit subject and Linux consumes it to
publish the complete score universe. Both use the shared codec in
`server/common/analysis_snapshot_codec.py` through `analysis_pool_receipt.py`.
Changes to this storage contract require a coordinated Windows/Linux release.

New snapshots use `zlib-base64-dictionary-columnar-json-v1`. The logical
preliminary and score schemas are unchanged. Canonical logical JSON still owns
`payload_sha256`; frozen row hashes, stock coverage, scores and all provenance
remain unchanged. `compressed_sha256` separately binds the stored zlib stream.

The representation contains non-table `metadata`, a global pool of complete
JSON cell `values`, and ordered column indices for each row table. Index zero
means absent; positive indices reference a whole value. Null, absent, booleans,
integers, floats and JSON-looking strings remain distinct. Table names, columns,
pool ordering and JSON bytes are canonical. Decoding restores independent
mutable cells before any business consumer receives the rows.

The Base64 storage ceiling remains 12 MiB. New storage JSON is decompressed
under a 128 MiB wire ceiling. Before allocating expanded rows, the codec computes
their complete canonical JSON length from reference counts and rejects anything
over 256 MiB. It also bounds rows to 10,000 per table, columns to 512 per table,
and total cells to 4,000,000. This separate expansion budget prevents a small
value dictionary from causing unbounded allocations through repeated references.

Previously sealed `zlib-base64-canonical-json-v1` receipts remain permanently
readable with their original hash and validation rules. Historical score JSON
retains its 128 MiB decompression ceiling. Historical preliminary JSON retains
its original exact level-9 stream validation and original size domain. New
producers emit only the dictionary encoding; no historical data is rewritten.

The September 10, 2026 production failure contained 5,546 analysis and scored
rows plus 80 candidates. Repeated event details and provenance produced about
173 MB of logical JSON and 14 MB of Base64, exceeding the storage ceiling.
Lossless value pooling reduces its storage JSON to about 38 MB and Base64 to
about 8.1 MB, while restoring the same complete canonical payload hash.

Regression coverage includes immutable synthetic receipts generated by the
deployed `95f343f` implementation, producer/consumer round trips, missing versus
null cells, mutable-object isolation, altered hashes, malformed indices,
noncanonical storage, compression trailers and expansion-budget rejection.
