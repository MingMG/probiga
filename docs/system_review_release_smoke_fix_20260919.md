# 系统审查版本的正式页面验收修复

2026-09-19，用户授权将系统审查版本交由 QMT 任务统一协调发布。目标 `4bc3b1c66b4452d1fa852473756029833e280048` 的正式发布在 `verify_account_login_api_and_page_smoke` 失败，唯一发布负责人随后执行正式回退/保护恢复。本任务没有另开发布或手工修改生产服务。

## 已确认原因

登录页面与脚本的发行版字节一致，登录状态及错误凭据路径也符合约定，但发布脚本额外硬编码检查 `login.js?v=1`。本次登录安全修复将缓存版本提升为 `v=2`，因此正确的新页面也必然被拒绝。这是正式验收与发行版不一致，不能通过降低缓存版本、删除字节校验或跳过鉴权检查解决。

同时复核到策略治理页面的可选正式检查仍要求首页原始 HTML 含旧静态导航节点和旧标题。本次导航已统一从 `APP_NAV` 渲染，目标容器仍存在；这些旧呈现断言也不再正确。

协调恢复时又确认一处既存 Bash 作用域缺陷：`controlled_guard_restore_and_finalize` 在声明本地 `scheduler_record` 前读取同名变量。在 `set -u` 下，没有调用方同名变量会直接失败；调用方存在同名变量时又可能取到错误状态。本次将参数绑定移到首次使用前，恢复语义和保护条件保持不变，并用真实 Bash 验证两种调用上下文。

## 最终行为

- `release_page_asset_url` 使用 HTML 解析器读取 prepared 页面中的唯一目标资源引用，要求同源 `/static/` 路径和单一非空版本参数；拒绝外链、重复引用、越界/不符路径和无效版本。
- 登录检查请求页面真实声明的版本化脚本地址，保留页面与脚本逐字节比较、初始化账户状态、错误凭据401以及登录/状态 API 的页面接线检查。
- 策略治理页面验证发行版 index/app 的实际字节、目标容器、`APP_NAV` 中的策略入口和导航渲染接线；不再把旧文案或重复静态侧栏当成正确性的必要条件。
- 恢复函数始终使用自身第三个参数构建安全调度状态，不再依赖调用方动态作用域；不修改发布保护、版本封存、回退条件、鉴权权限、QMT 采集或调度所有权。

运行边界：代码改动在受信发布流程的页面验收，生产执行仍由获授权的唯一负责人协调 Windows 与 Linux，不增加旁路或第二套发布路径。
