# 采集巡检与回执修复

东财概念行情曾被拿来与 QMT 的 1,289 项目录比较，导致原生完整的 504 项行情被判为缺失。巡检现在读取最后一次成功发布的原生回执，核对执行身份、回执哈希、源日期，并重新校验实际入库数据。收盘边界直接使用发布器的正式交易日规则。旧目录比例检查已删除。

新闻巡检保留目标交易日的新闻数量和近期公告数量要求，允许目标交易日之后、检查时间之前的真实新闻。周末新增新闻不会再使周五的数据检查失败，未来时间仍会失败。这两项检查已纳入定时采集完整性巡检。

调度器过去把 stdout 后的大段 stderr 截成末尾 60 KB，可能丢掉公告分片的 PROGRESS 或源错误回执。终端记录现在为有上限、已脱敏的原始机器回执保留空间。未完成批次仍不记作成功，超大或损坏回执不被截成有效回执。

## 发布范围

巡检文件 `tools/data_quality_check.py` 属于 Linux 服务端。终端回执保留逻辑位于 Windows 与 Linux 共用的 `server/api/scheduler_runtime.py`，影响两端调度执行记录，因此整体为跨端发布，使用合并 main 的正式协调交接。数据库结构、源数据字段、任务归属及 QMT 登录均未修改。

## 验证

416 项测试及 73 个子测试通过，覆盖普通定时回执、发布补采回执、错误执行身份、未来日期、缺失目录凭证、源回执与实际数据库价格不符、长日志、多字节截断与秘密脱敏。生产只读回读已确认东财行情、日线、资金流凭证及新闻检查通过。

全市场分钟接口验收使用现有生产版本的原生请求、并发器和分钟网格校验，只记录证据，不改写业务数据。公告修复继续使用正式任务的受保护断点；在整池验证完成前保留未完成状态。

## 公告连续补采

公告完整历史分片的 `PROGRESS` 回执仍为未完成状态，不能生成成功证据。调度器现在单独识别有实际新增进度、合法字段与哈希、连续代次证明且位于本次执行时间范围内的回执。得到本版本发布授权后，正常分片按任务配置的起跑间隔续跑；真实源故障、零进度或损坏回执仍使用原有失败退避。

发布交接期间，待续跑的公告任务尚未获得采集授权时，标准研究任务会暂缓占用独占执行名额。公告任务仍必须通过原有授权、主机归属和工作名额检查。已完成、已禁用、尚未到期、不可重试的阻断，以及真实故障的退避，不会触发这项等待。相同规则也为下一段已验证进度保留执行机会。

变更位于共用的 `server/api/scheduler_runtime.py` 与 `server/common/scheduler_validation.py`，因此继续按跨端调度契约协调发布。此次没有修改源接口或受保护历史账本，也不触发 QMT 登录。新增测试覆盖真实调度入口在授权空档不启动任一任务、授权不被提升、错误回执不缩短退避，以及正常分片无需在完成后再等 15 分钟。
