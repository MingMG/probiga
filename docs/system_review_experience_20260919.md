# 产品体验与展示准确性审查 · 2026-09-19

范围：数据获取之外的交易页、看盘闭环、问答、历史复核与新首页展示。运行边界为 **Linux/server**：修改静态页面与服务端页面入口，不改变 Windows/QMT 采集、协议、数据库结构或任务所有权。

## 产品判断

首页需要回答四个问题：市场发生了什么、哪些变化与我的股票有关、下一步应核对什么、以前的判断后来怎样。原有页面把交易后台、研究状态和数十个入口同时推给用户；诸如批次、来源、权限的技术状态挤占了看盘信息。数据虽然多，但当前事实、研究推断、模拟执行与历史记录缺乏统一边界。

最终信息路径应是：**市场事实 → 板块线索 → 个股依据 → 自选或持仓跟踪 → 事后验证**。每一环保留对象与日期，允许回到上一层；实现术语放进诊断详情。没有可信证据时显示缺失，不提供虚假的零、胜率、空仓或持有结论。

## 已落实的独立页面修复

| 原问题 | 影响 | 最终处理与证据 |
|---|---|---|
| `Number(null)`、`Number('')` 将未知收益、比率与胜率变成 0 | 用户会把未取得的数据误解为已测量的结果 | `server/static/js/trading-v3.js` 的 `metricNumber`、`fractionPct` 与 `trading-v2.js` 的 `n` 区分缺失、非法类型和真实 0；预期收益缺失不能认作已校准 |
| 历史持仓的 SELL 覆盖页面标题，出现“今天立即退出” | 历史证据被当成当前操作 | `renderChrome` 先处理历史模式；今日动作与新买资格显示历史只读。说明历史模式只是当前登记持仓套用历史证据，不能还原历史账户 |
| 持仓读取失败仍显示 0 只、无强制卖出 | “不知道风险”被误解为“没有风险” | 持仓读取失败、待加载、WAIT_DATA 分开显示。`holdingStrategyPayload` 校验记录与汇总数量；证据不完整时不提示继续持有或新增买入 |
| `remaining_quantity || quantity` 将明确 0 恢复成原始数量 | 已无剩余仓位仍展示持有 | 使用首个有效数值，保留 0；模拟账本请求失败时清除持仓结论 |
| 结构化先验与校准概率都显示百分比 | 研究评分容易被误当历史胜率 | 仅 `OOS_CALIBRATED` 显示“历史校准”；其他先验显示“研究评分 / 100”，同时保留性质列 |
| 连续跟踪筛选和时间线请求没有次序保护 | 旧日期或旧股票响应覆盖当前选择 | 使用请求序号和页面加载序号；新查询清除旧证据；失败明确显示不可用 |
| 时间线包含假设形成后的全部事件，但未说明知识边界 | 后续证据容易被看作当时已知 | 时间线明确标注为“完整后续验证”，必须按每条发生时间复核 |
| 点击策略股票跳外部 K 线 | 从策略到系统详情、自选管理的路径断开 | 证券按钮发同源 `probiga-open-stock-detail` 消息；独立页使用 `/?tab=workbench&stock_code=...`；只接受六位证券码 |
| 模拟页面接口失败后旧快照仍留着，附属接口失败伪装空对象 | 页面可以展示错误的空仓、无信号与已通过状态 | 显式保存请求错误；失败的展示区域显示不可核验，隐藏原结论；核心快照失败同时清空账户摘要 |
| AI 页面将回答提供者称为“数据源”，并把桥接细节放在首屏 | 模型输出与经过核验的行情事实混为一谈 | `ai-stock.html`、`ai-general.html` 改为回答来源、事实与观点核对；每条回答标明模型分析性质；请求、来源尝试、时间与错误保留在诊断详情 |
| 问答无法接续个股研究对象 | 用户需要反复手输股票与问题 | `ai-chat.js` 支持 URL `stock_code`、`question` 预填；只写入可编辑草稿，绝不自动发送。研究对象链接回系统事实页；未知回答来源显示“来源未确认”，不默认冒称 GPT |
| 独立雷达与主系统雷达是两套不同能力页面 | 独立页缺少新鲜度、自选关联与详情路径 | 确认主系统自行渲染雷达，不嵌入独立路由；删除 `market_radar.html`。发布审查代理将 `/market-radar` 统一重定向到 `/?tab=market-radar` 并覆盖入口回归 |
| 登录返回地址只检查字符串前缀并重复解码 | 反斜杠路径可被浏览器解析为外站，带编码问题的研究链接也会损坏 | `login.js` 使用浏览器 URL 解析结果校验同源，拒绝返回登录页；保留查询与片段编码，登录后可以接续原研究对象 |

上述变化不授予真实交易权限，不修改后台决策模型或数据获取流程。

## 新首页交叉审查闭环

对 `server/static/js/market-workbench.js` / `server/static/css/market-workbench.css` 的九项独立审查发现已由主代理处理，复核以函数与行为测试为准。没有编辑首页源码。

| 原发现 | 最终状态 |
|---|---|
| 未来日期只清除广度，成交额和板块仍漏出 | `model` 在读取任何市场指标前统一排除缺日期或晚于请求日的市场快照 |
| 自选读取不存在的时间字段并忽略 stale | `renderWatch` 使用实际 `quote_trade_date`、`quote_snapshot_at`、`quote_status`、顶层及行级 `snapshot_stale`；旧报价/待核验失去实时配色 |
| 盘前打开页面因旧时钟永不开始刷新 | 先刷新权威时钟，再决定是否读取；异步时钟返回后再次检查页面取消状态 |
| 自动刷新只更新市场和自选、策略停留盘前 | 自动更新全部六类已定义证据；日期、批次和数据日不一致时禁止合成候选结论 |
| 历史可读性与当前策略资格混淆 | 历史只读证据单独显示；结合主系统策略真值函数校验数据日期、下一执行日和批次一致性，不把历史可读记录当当前可执行 |
| 空股票码补成 000000 仍出现入口 | `stockButton` 只接受原始六位有效代码，000000 与非法值不生成按钮 |
| 事后回填旧日期判断被当作当时预测 | `retainedRows` 要求留存时间不晚于观察日；展示后续指数变化而不称策略收益或预测胜率 |
| 板块标题暗示资金净流入 | 改成“成交与关注集中在哪里”，显式解释热度/成交额口径不能推出资金净流入或买入资格 |
| 小屏家数 KPI 与自选卡可能溢出 | 增加窄屏 KPI 换行与自选卡换行；这是源码与布局规则复核，未完成真实浏览器 320–390px 视觉验收 |

## 热股排行与个股闭环

后续集成测试暴露的热榜问题在原 `origin/main` 中已存在，本次按真实产品缺陷修复，不因属于基线而保留：

- 历史/休市仅请求所选日期快照；盘中只在权威时钟的当前日读取原有实时接口。任何缺日期、未来日期或未声明的错日响应都不能成为当前榜单。允许的单源历史回退明确显示“所选日期 / 最近可用日期”，不修改全局日期选择。
- 请求按日期、子页与序号绑定；旧响应不能覆盖新日期或新来源。请求 Promise 完整返回，自动刷新不能抢占未结束的手动请求，旧请求结束也不会解除新请求的锁。
- 读取失败与真实空榜分开；只有相同日期、相同来源才保留上次成功表，并在表头明显标注旧数据。不同日期/来源的旧表立即清除；新浪停止服务原因原样作为不可用原因展示。
- 来源摘要只展示实际来源计数或持久化证据中已证明的来源；不再宣称固定四源。部分源错误有提示，未知涨跌与平盘不计作上涨；综合分不称盈利概率。
- 自动刷新从每秒强制刷新改为 60 秒普通 GET，并在刷新权威时钟后检查是否盘中。**没有发送 `fresh=1`**：后端该参数会缩短缓存并触发外部获取；本次保留原普通 GET 语义，未新增获取路径、触发方式或采集调度。
- “我的关联”显示当前自选和所选日经日期/完整性校验的策略关联，均不参与排名。自选请求使用真实 `/api/portfolio/codes` 路径，避免热数据 API 前缀造成 404。旧读不能覆盖新读；读取失败保持“待核验”，不声称未入选。
- “查看依据”进入已有股票详情，通过详情内唯一“加自选”入口完成用户点击的写操作，不另造快捷加/撤销入口。成功写入后刷新热榜只读关系，休市也能立即看到更新。
- 股票详情的股东人数变化改为中性事实，不直接判定利好/利空。

旧测试中硬编码缓存号、双布局/六个固定首层入口、尚未存在的热榜快捷加/撤销接口，已按最终唯一导航与唯一自选写入口更新。保留并增强乱序、日期隔离、失败保留、实际渲染顺序与跳转行为测试，未通过削弱真实数据边界让测试转绿。
