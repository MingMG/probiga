# QMT 采集失败时恢复登录

正式日线、分钟采集在连接或执行失败后，同步检查本机 QMT。终端退出时由现有 Windows 桌面进程拉起；确认处于登录界面后，从当前 Windows 用户的凭据管理器读取 `ProBigA/AppLogin/qmt`，完成一次登录，恢复正式数据桥，再重试失败的交易日。没有新增定时检查、后台登录服务或新的调度任务。

每次采集运行最多恢复一次，开始、采集和结束时的连接检查共用这个限额。已完成分区继续保留。重试前后都验证原来冻结的策略身份，数据校验、分区哈希、调度归属及原任务超时不变。已在线时不重复登录；身份不匹配、数据证据不完整和未确认子进程退出的超时不会触发认证重试。

## 本机前提

- 当前交互桌面可用，Windows 凭据管理器已有经验证的 QMT 凭据。密码不写入项目、环境变量、命令参数或采集日志。
- 固定安装为 `D:\国金证券QMT交易端\bin.x64\XtItClient.exe`，版本 `2.1.19.0`，登录窗口 DPI 为 96。程序同时检查安装资源、唯一进程、窗口布局、前台归属和输入框内实际闪烁的光标。其他版本或布局需要重新验证识别规则。
- 采集必须运行于正式 Windows 生产根目录，继承完整的 `PROBIGA_BUILD_COMMIT_SHA`。登录后需要恢复策略时，调用已有的 `reload_big_qmt_strategy.ps1 -ColdStartRecovery`，继续受原有发布身份、恢复凭据和回滚约束。

QMT 通过当前用户的 Explorer 桌面启动，不成为采集进程的子进程。这样调度器的 `KILL_ON_JOB_CLOSE` 仍管理采集工作，而不会连带关闭新启动的终端。已有进程守护和采集恢复使用同一个 `Local\ProBigA.BigQmtStrategyRecovery` 互斥锁，避免重复启动或同时操作界面。

## 失败行为

界面遮挡或输入框焦点无法确认时，不提交登录。真正点击登录前才持久记录一次尝试；拒绝登录、额外验证或提交结果不确定会阻止后续任务连续尝试同一份凭据。记录只包含版本、凭据修订时间和固定错误码，位置为生产根目录的 `data/qmt_terminal_login_recovery.state.json`。确认人工登录成功，或重新登记凭据后，可恢复后续尝试。

恢复成功的依据是同一终端进程的新鲜数据桥心跳；采集成功仍以完整分区和正式数据认证为准。MyQuant SDK 令牌、上游服务中断、数据缺失等问题不由 QMT 软件登录处理。

## 验证

回归覆盖采集重试预算与原参数、完成分区保留、身份和认证阻断、凭据输出脱敏、原生输入释放、登录状态持久化、前台变化、重复启动互斥及正式策略恢复回执。Windows 实机另需验证安装和在线识别、原生光标识别、桌面启动脱离采集 Job，以及空闲时真实登录恢复后重新读取数据。
