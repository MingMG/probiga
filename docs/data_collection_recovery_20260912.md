# 数据采集修复与验收

本次范围为数据获取、采集状态、补采及必要的发布依赖。策略计算、订单和消息发送不属于验收操作。

## 数据库恢复后发现的问题

2026-09-12 12:35，Windows MySQL 8.4.11 在行情批量 INSERT 的 DECIMAL 转换警告路径中崩溃。当时 E 盘仅剩约 133 MB。13:19 服务完成原生崩溃恢复；随后主接口恢复 HTTP 200。这个健康结果不足以证明行情表完整，后续 CHECK TABLE 确认 `idx_sc_code` 已损坏。

- 5,562 行原始行情可从主索引完整读取，证券唯一索引和时间索引与主索引一致。修复前完整行已保存在本次运维目录，源快照日期仍为 2026-09-11，未刷新为今日数据。
- 199 份已关闭的 binlog 已使用 NTFS 透明压缩，逐份核对 SHA-256、长度和最后写入时间；保留全部文件、原索引和三天保留期。可用空间从约 0.54 GB 恢复到约 36.98 GB。正在写入的日志和业务数据文件没有参与压缩。
- 行情消费改为交易时段按证券唯一键更新，只删除新全量快照范围之外的证券；保留存量行 id。休市全量、关注列表和显式刷新入口均不写行情或产生新采集回执。
- 入库前验证唯一证券键和 DECIMAL(50,6) 实际契约，统一绑定 Decimal；拒绝非有限数值、越界值、非正价格和负成交量额。该改动去除已观察到的浮点转换警告诱因，不将其宣称为 MySQL 引擎崩溃的完整根因证明。
- 共享表存储迁移由正式 broker 的 writer fence 内执行：先验证证券唯一索引与主索引一致，移除同字段的冗余 `idx_sc_code`，再校验完整行哈希和 CHECK TABLE。运行时不执行修复 DDL。
- QMT 发布预检按目标 PID 枚举并唯一匹配真实账户窗口。编辑器处于前台时，不能用 Process.MainWindowTitle 的编辑器标题误报登录失败。

上述代码的发布边界为 Windows/QMT 与 Linux/server：Windows 行情写入、QMT 发布窗口定位和共享表索引迁移共同变化。必须部署合并后的 main，按两端发布流程获得真实原生模型和调度器回执。

隔离 MySQL 8.4.11 已验证跨批次更新保留 id、定点数无服务端转换警告、第二批失败回滚整次写入、坏字段/坏索引契约不改变存量行，以及索引迁移保留全部数据且可重复执行。QMT 实际运行模型切换仍须独立验证；窗口工具返回错误画面不能算作已切换。

## 发布边界

这是 Windows/QMT 与 Linux/server 的协调发布：Windows 原生桥接动作、调度任务所有权、采集回执、共享数据表和分红事件结构同时变化。两个端点必须运行同一个已合并 main 的修订。数据库结构只通过现有 writer fence 内的 migrator 迁移，运行时只检查结构；不重启无关数据库或交易服务。

## 固定的数据语义

- 证券范围来自目标日期的冻结目录，不能用昨天有日线的股票代替今天应采的股票。
- 原始证券身份、市场、业务日期和必需数值均须验证。源未提供的可选字段保留空值；不能补零冒充真实值。
- 网络成功、登录成功、方法存在都不能证明取得数据。BigQMT 能力检查必须验证真实响应及其冻结模型身份。
- 采集失联时在该次采集内进行一次同步登录恢复；权限、源字段、数据日期或模型身份错误不能触发无效的重复登录。
- 写入成功要用正式目标数据库回读验证。来源、目录和实际结果不一致时不能发布完整回执。
- `COMPLETE`、`PARTIAL`、`FAILED` 分别表示完整、部分和失败。调度中的部分完成是 `DEGRADED`；非交易时段 `SKIPPED` 保留最近一次真实执行状态，并独立记录本次跳过历史。
- 停牌或没有交易必须有匹配日期和目录的正式无记录证明；“请求返回空”本身不是证明。
- 当前快照不能改日期填入历史。缺失的时点成员、新闻或盘中观察数据只有原始历史证据存在时才能补回。

## 核查项

| 工作 | 修复后的验收要求 |
| --- | --- |
| QMT 终端与能力 | 保存的 Windows 凭据可用于失败触发的恢复；真实股票、指数、目录、日历响应绑定同一原生模型 |
| 股票及指数分钟线 | 可选均价为空不误判；无交易证明与日线互相验证；目标日为已完整结束的自然日内交易日 |
| 原生分钟资金流 | 唯一 BigQMT `transactioncount1m` 动作；保留四类原始资金字段；全零 L1 响应不能证明 VIP 数据权限 |
| 公共分钟行情及资金流 | 目标目录覆盖新股和复牌股；固定六个独立请求通道保留节流；主线程暂存和原子发布；缺失如实回执 |
| 日资金流 | 包含有实际交易的北交所股票；日线读取 Kline 库、资金流读写 minute 库、目录和日历读取 primary 库 |
| 盘中累计资金流 | 目标日目录与原生源时间共同验证；保留实际缺失集合，不把达到阈值当作全量 |
| 东财概念日线 | 最新已闭市日期可使用原生收盘 OHLCV；历史日期必须取得真实历史记录 |
| 同花顺概念及成员 | 原生概念标识、目录数量和逐概念成员数量全部核对；限流、登录跳转或空响应不得替代成员清单 |
| 分红 | 按证券及报告期识别事件；公告日继续表示公告时间；保存完整股东方案、原始修订和批次快照；原生字段缺失单独标明 |
| 财务未披露证明 | 使用官方 PDF 正文、真实公告时间和原始文件哈希；后续披露使对应未披露证明失效；不刷新旧证明时间 |
| 新闻与外围行情 | 每个正式来源独立统计；单个来源正常不能掩盖其他来源停更；部分成功保留已取得数据并报告缺失 |
| 长任务与补采 | 保留持久进度；只有确认原执行进程不存在才修复遗留 RUNNING；采集不反过来等待依赖其结果的策略任务 |

## 已确认的外部缺口

同花顺公开目录包含尚未上市的新股。用同源 IPO 页面增加候选并逐只验证后，390 个概念中 387 个成员数量闭合，已证实 70,520 条关系；新能源汽车 1060/1061、一带一路 792/793、抽水蓄能 80/81，仍有 3 条关系缺少可核验来源。受限完整名单需要同花顺登录，报价分页总数不能代替概念原生成员总数。完整性尚未证明，因此本版不切换同花顺正式入口，也不发布未接入的候选代码。

2026-09-08 的行业/概念时点快照目前只发现部分 QMT 残留响应，不能用现时成员回填。日资金流和概念日线已验证最新闭市日来源，较早历史仍须由原日期的源数据补齐。002731 的半年报未披露属于公司本身的数据缺口；新官方证明只能说明未披露，不能代替财务报表。

## 验收顺序

1. 源端真实只读采集与有意义的回归测试。
2. Linux CPython 3.14 完整锁定 wheelhouse 的哈希校验、无索引安装、依赖检查和原生模块运行。
3. 提交会话分支、合并 main，通过现有 broker 协调发布两端。
4. 正式任务采集、正式数据库回读、任务状态和回执复核。

发布前汇总验证覆盖 100 个测试模块：2697 项通过、73 个子测试通过、1 项跳过。另有 `test_hot_rank_api_safety.py` 的 11 项融合热榜测试失败；在生产基线 `83d193273db5a087bdd9aa88a4f4c837791626d7` 的独立工作树中复现了完全相同的 11 项失败，原因是现有融合 API 的双源、已存融合结果及刷新缓存行为与测试期望不一致。本次未修改该 API，也未删除或放宽这些测试；基线和候选的 JUnit 对照保存在 `runtime/`。48 个生产 wheel 的 Linux CPython 3.14 隔离安装、依赖检查、原生运算及官方 PDF 解析已经通过。

代码测试、只读源探针与正式生产入库是不同证据，报告时分别列示。发布成功不等于历史缺口已经全部补齐。实际证据保存在本次工作目录的 `runtime/`，不将生产数据、账户凭据或一次性探针纳入发布制品。
