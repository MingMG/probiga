# AlphaPilot 风格策略中心改造方案（待确认）

> 状态：已实现 v1。本文档保留原始设计边界，并补充了当前实现的落点；新增实现已通过全量测试。
>
> 目标：参考 AlphaPilot 策略中心的交互与表达方式，把现有 ProBigA 的推荐、策略、市场状态、事件门禁和模拟交易能力整理成一个独立的“策略中心”。所有输出仍然只是研究建议；不会接入券商，也不会在未经明确确认的情况下执行模拟盘或实盘交易。

> 当前实现：后端位于 `server/engine/strategy_center.py` 和 `server/api/routers/strategy_center.py`；前端入口位于 `server/static/index.html`、`server/static/js/app.js` 和 `server/static/css/style.css`。数据库表在首次执行策略中心运行或启停操作时按需创建。

## 1. 现状与改造原则

当前项目已经具备以下基础能力：

- `st_recommended_stocks` 已保存推荐分数、策略归属、适用策略、信号状态、入场区间、止损、止盈、盈亏比、置信度、证据链和复盘收益。
- `RecommendationGate` 已提供 `ALLOW / SUSPENDED / BLOCK` 三档推荐门禁。
- 已有市场情绪、风格切换、技术风险、决策雷达、板块轮动和数据完整性接口。
- 已有运行参数校准、失败归因、模拟交易统计和回测/前向模拟接口。
- 现有前端已经有 AI 推荐页、策略筛选、风险状态和模拟交易页。

本次不重写上述链路，采用以下原则：

1. 新增独立的策略中心视图和统一数据契约，逐步接入现有数据。
2. 研究信号、策略权重和风控门禁分层保存，避免把一个股票的多个策略信号压缩成一条记录。
3. 缺数据、数据过期或门禁未通过时显示“不可确定”，不使用默认值伪造确定性结论。
4. 策略停用只影响后续新信号，不删除历史信号、收益和复盘数据。
5. “模型置信度”表示模型对当前信号的稳定程度，不等同于收益概率。

## 2. 策略目录

策略键名固定为英文，中文名称用于界面展示和报告：

| 策略键 | 名称 | 类型 | 首版适配重点 |
|---|---|---|---|
| `multi_factor` | 多因子 | 综合 | 基本面、估值、技术、资金、情绪的标准化合成 |
| `value_quality` | 价值质量 | 中长线 | 低估值、盈利质量、现金流、分红和风险过滤 |
| `trend_breakout` | 趋势突破 | 趋势 | 均线结构、突破、成交量确认、回踩有效性 |
| `sector_rotation` | 行业轮动 | 板块 | 行业资金、板块宽度、相对强弱和个股跟随 |
| `low_volatility` | 低波动 | 防守 | 波动率、回撤、贝塔、稳定现金流和高股息 |
| `oversold_reversal` | 超跌反转 | 反转 | 超跌程度、止跌结构、资金承接和反弹空间 |
| `event_driven` | 事件驱动 | 事件 | 公告、新闻、产业链关系、事件时效和风险级别 |
| `machine_learning` | 机器学习 | 模型 | 只使用可追溯的已训练模型；无模型或样本不足时不生成确定性信号 |
| `intraday_entry` | 盘中入场 | 盘中 | 30 分钟确认、实时价格、量价和指数/板块同步 |
| `etf_defense` | ETF 防守 | 防守 | ETF 资金、指数趋势、市场风险和防守替代方案 |

首版不要求十套策略都拥有完全独立的计算引擎。没有独立数据或训练结果的策略可以先输出 `INSUFFICIENT_DATA`，不能用复制其他策略分数的方式冒充独立模型。

## 3. 市场状态

界面保留四个状态名称，并同时展示判定证据、置信度和更新时间：

| 状态键 | 界面名称 | 主要判定依据 | 默认策略倾向 |
|---|---|---|---|
| `trend_bullish` | 趋势偏多 | 指数趋势、市场宽度、板块延续、资金和波动率 | 趋势突破、行业轮动、多因子正常权重 |
| `high_range` | 高位震荡 | 指数接近高位但宽度收窄、量价背离、热点轮换加快 | 降低追高，偏向价值质量、低波动和等待回踩 |
| `risk_declining` | 风险下降 | 风险释放、指数/板块止跌、宽度和资金出现修复 | 逐步恢复防守和低位确认策略；新买入仍需门禁 |
| `extreme_event` | 极端事件 | 重大事件、指数急跌、波动激增、数据异常或事件风险高 | 停止新增买入，保留风险提示和防守观察 |

状态优先级建议为：

`extreme_event` > 数据不可用/过期 > `high_range` > `risk_declining` > `trend_bullish`。

“风险下降”在实现时需要确认它是“风险水平下降、市场修复”，还是“风险偏好下降、市场转防守”。在未确认前，文档按前者设计，并在界面显示判定解释，避免只显示一个容易误解的标签。

## 4. 策略权重、自动降权和事件门禁

每个策略拥有以下运行属性：

- `enabled`：是否启用。
- `base_weight`：策略基础权重。
- `effective_weight`：当前市场状态和数据质量下的有效权重。
- `state_multiplier`：市场状态适配系数。
- `performance_multiplier`：近期复盘表现系数。
- `data_quality_multiplier`：数据完整性和新鲜度系数。
- `gate_status`：`PASS / REDUCE / BLOCK`。
- `gate_reason`：可读的降权或阻断原因。

建议计算方式：

```text
effective_weight = base_weight
                 × state_multiplier
                 × performance_multiplier
                 × data_quality_multiplier
```

最终结果需要限制在配置的安全范围内。任一硬性事件门禁为 `BLOCK` 时，策略不能通过提高其他分数绕过门禁；风险状态下可以将有效权重降为 0，并把信号转为 `WATCH / SUSPENDED`。

策略运行参数只允许通过受保护的管理接口修改，并保留版本、修改时间、修改人和回滚信息。普通研究页面只能切换已授权的启用状态，不能直接改写止损、仓位或门禁阈值。

## 5. 统一信号模型

每个“交易日 + 股票 + 策略”保存一条策略信号。建议字段如下：

| 字段 | 说明 |
|---|---|
| `trade_date` | 信号对应的交易日 |
| `stock_code / stock_name` | 股票标识 |
| `strategy_key` | 产生信号的策略 |
| `market_state` | 生成信号时的市场状态 |
| `signal_direction` | `BUY / HOLD / SELL / NO_SIGNAL` |
| `signal_status` | `READY / WATCH / SUSPENDED / BLOCKED / INSUFFICIENT_DATA` |
| `raw_score` | 策略原始分数 |
| `effective_score` | 应用权重和门禁后的分数 |
| `model_confidence` | 模型置信度，0–100 |
| `today_signal` | 今日信号摘要 |
| `entry_low / entry_high` | 观察或入场区间 |
| `trigger_conditions` | 完整触发条件，结构化保存 |
| `stop_loss` | 止损价 |
| `take_profit_1 / take_profit_2` | 分级止盈价 |
| `no_chase_price` | 禁止追高价；无数据时为空 |
| `risk_level` | `LOW / MEDIUM / HIGH / CRITICAL` |
| `risk_reward_ratio` | 盈亏比 |
| `evidence_chain` | 数据源、指标、公告、板块和门禁证据 |
| `data_snapshot` | 生成时的数据日期、来源和覆盖率 |

候选池表格默认展示：优先级、股票、入选策略、观察区间、完整触发条件、止损、止盈、风险、置信度、信号状态和数据日期。原型中的招商银行、中国神华、中国移动三行可以作为验收 fixture，但不能硬编码进生产逻辑。

## 6. 相反信号冲突裁决

同一股票同时出现相反信号时，必须保留全部原始信号，并按以下顺序裁决：

1. **硬门禁优先**：重大事件、数据过期、交易范围不合规或 `BLOCK`，直接阻断新增买入。
2. **风险退出优先**：高等级 `SELL / REDUCE` 信号优先于普通 `BUY`，至少转为风险观察；不因为买入策略数量多就覆盖硬性风险。
3. **有效权重投票**：剩余信号按 `effective_weight × model_confidence` 汇总多空方向。
4. **一致性门槛**：多空差距不足或置信度不足时，输出 `WATCH / CONFLICT`，不强行生成买入结论。
5. **可解释输出**：展示支持买入的策略、支持卖出的策略、各自权重、门禁原因、最终裁决和失效条件。

建议统一输出：

```json
{
  "final_direction": "WATCH",
  "final_status": "CONFLICT",
  "buy_score": 61.2,
  "sell_score": 58.9,
  "dominant_strategy": "low_volatility",
  "blocking_reasons": [],
  "conflict_summary": "价值质量和低波动偏多，事件驱动提示风险，暂不形成新增买入信号"
}
```

## 7. 建议的数据表分层

不建议把十套策略的独立信号继续塞进 `st_recommended_stocks` 的单行记录。建议新增策略中心专用表；现有表继续作为 AI 推荐和兼容读取入口。

### 7.1 `st_strategy_center_config`

保存策略启停、基础权重、版本、配置 JSON、更新时间和操作审计。

### 7.2 `st_strategy_center_run`

保存一次策略中心运行批次：交易日、运行时间、市场状态、状态置信度、数据快照、模型版本、运行状态和错误信息。

### 7.3 `st_strategy_center_signal`

保存“批次 + 股票 + 策略”的原始信号、有效权重、状态、入场计划、风险、证据链和数据快照。

### 7.4 `st_strategy_center_conflict`

保存同一股票的多空输入、裁决结果、裁决规则、阻断原因和证据，方便复盘与前端展开。

### 7.5 `st_strategy_center_metric`

保存策略级日快照和回测汇总：今日信号数、收益、最大回撤、胜率、盈亏比、Profit Factor、样本数、统计区间和数据状态。

已有 `st_strategy_snapshot` 的模拟交易统计可作为数据来源，但不能把缺失的最大回撤、Profit Factor 和样本数显示为“0”；没有足够样本时显示“暂无样本”。

## 8. API 方案

建议新增独立路由模块，例如 `server/api/routers/strategy_center.py`，由 `server/api/main.py` 统一挂载。建议接口如下：

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/strategy-center/overview` | 市场状态、全局门禁、策略卡片、候选池摘要 |
| GET | `/api/strategy-center/market-state` | 四状态、判定证据、置信度、更新时间 |
| GET | `/api/strategy-center/strategies` | 十套策略配置、启停状态、有效权重和指标 |
| POST | `/api/strategy-center/strategies/{strategy_key}/toggle` | 单独启用/停用，需管理鉴权和审计 |
| GET | `/api/strategy-center/candidates` | 按交易日、策略、分类、状态和风险筛选候选池 |
| GET | `/api/strategy-center/stock/{stock_code}` | 单股的全部策略信号和冲突裁决 |
| GET | `/api/strategy-center/compare` | 策略横向比较和时间区间指标 |
| GET | `/api/strategy-center/conflicts` | 反向信号和裁决记录 |
| POST | `/api/strategy-center/run` | 受保护的策略中心运行入口，复用现有数据门禁 |

现有以下接口继续复用：

- `/api/hot-data/market-sentiment`
- `/api/hot-data/style-switch-signal`
- `/api/hot-data/tech-risk-signal`
- `/api/hot-data/decision-radar`
- `/api/hot-data/sector-rotation`
- `/api/hot-data/recommended-stocks`
- `/api/hot-data/recommended-stocks/gate`
- `/api/hot-data/strategy-runtime-params`
- `/api/sim-trade/dashboard`
- `/api/sim-trade/backtest/report`

所有返回均应带 `data_date`、`generated_at`、`source_status`、`model_version` 和 `is_stale`。前端不能只根据 HTTP 200 判断数据可用。

## 9. 前端页面方案

在现有“选股工具”下新增“策略中心”入口，和 AI 推荐页并列；不删除现有 AI 推荐页。

页面顺序建议：

1. **全局状态栏**：当前市场状态、状态置信度、数据日期、数据新鲜度、全局新增买入门禁。
2. **策略卡片区**：十套策略的启用开关、分类、今日信号、有效权重、收益、回撤、胜率、盈亏比、模型置信度和门禁状态。
3. **筛选和横向对比**：按策略分类、启用状态、市场状态、信号方向、风险级别筛选；允许选择多个策略比较。
4. **候选股票池**：展示观察区间、触发条件、止损止盈、禁止追高价、风险和信号裁决。
5. **冲突面板**：点击股票查看所有策略原始信号、权重、证据和最终裁决。
6. **证据与数据状态**：展开查看公告、板块、指数、资金、行情覆盖率和失效时间。

界面状态约定：

- `BLOCKED`、`EXTREME_EVENT` 和数据过期使用醒目的风险样式。
- `WATCH`、`CONFLICT` 和样本不足使用观察样式，不显示成绿色买入。
- 指标缺失显示“暂无样本/暂无数据”，不显示 0。
- 所有策略切换操作显示“仅影响后续研究信号”的提示。
- 页面保留现有“未经明确确认不执行任何交易”的安全说明。

## 10. 原型候选池的接入方式

用户提供的 2026-07-20 候选池可作为首版展示验收样例：

- 600036 招商银行：防守相对强势、低估值高股息。
- 601088 中国神华：能源相对强势、高股息趋势回踩。
- 600941 中国移动：低贝塔高股息、运营商防守。

实现时不把价格、日期和触发条件写死在前端。应由交易日、收盘数据、集合竞价、实时行情、板块状态和公告数据生成；缺少 08:45 后复核所需数据时，显示“待复核/不生成确定性动作”。

## 12. 验收标准

- 页面能稳定列出十套策略，且每套策略的键名、分类和启停状态可追踪。
- 四种市场状态的当前值、判定证据、置信度和数据时间可见。
- 风险状态或重大事件下，新增买入信号自动停止或降级，并显示原因。
- 策略权重变化能解释为市场状态、历史表现或数据质量导致，不能只显示一个无法追溯的分数。
- 同一股票出现相反信号时，最终结果可重复、可解释，并保存全部输入信号。
- 候选池支持策略分类筛选、横向比较、完整触发条件和风险字段展示。
- 收益、回撤、胜率、盈亏比和 Profit Factor 均来自真实统计窗口；样本不足不伪造数值。
- 交易确认边界不变：系统只输出研究候选、观察和建议，不登录券商、不下单、不撤单、不自动执行任何交易。

## 13. 待确认事项

在开始改代码前，请确认以下默认方案是否可接受：

1. “策略中心”作为新页面，与现有“AI 推荐”并列，不替换现有推荐页。
2. 十套策略先建立统一数据契约；没有独立数据/训练模型的策略显示样本不足，不伪造结果。
3. 策略启停写入配置表，并要求管理员鉴权、审计和可回滚。
4. “风险下降”按“风险释放后市场修复”理解；如果你想表达“风险偏好下降、转防守”，需要改状态判定文案和权重方向。
5. 2026-07-20 的三只股票只作为验收样例，生产数据仍从现有行情、公告、板块和数据门禁链路获取。
