# 数据监控 504 事件与修复记录

日期：2026-09-23。

## 现象与根因

生产 Nginx 返回 `504 Gateway Time-out`。Nginx 自身正常，后端 API
进程仍在监听 `127.0.0.1:8000`，但已无法及时处理请求。API 的
`probiga.service` 常驻内存约 1.06 GiB，并持续触发 900 MiB 的
`MemoryHigh` 节流；数据监控线程同时保留多日、全数据集的缺失明细和
完整 CSV 导出，使进程内存随扫描结果增长。

## 最终修复

- 日常监控缓存只保留最多 200 条展示明细，同时单独保存精确缺失总数。
- CSV 不再在后台扫描时为每个日期和数据集预生成；用户请求导出时，仅
  针对所选日期和数据集重新读取并生成完整 CSV。
- 单个依赖日上下文的检查失败不再阻塞可独立读取的数据源。
- 发布范围分类器将 `server/api/data_monitor.py` 明确登记为 Linux 私有
  模块；本次因同时修改发布范围合同，仍按协调发布执行。

## 验证与恢复边界

单元测试覆盖明细上限、精确计数、按需完整导出、目标数据集重读及独立
数据源容错。生产发布必须继续使用受信 broker；若切换中断，使用受保护
恢复账本恢复旧运行时，禁止手工清除 guard、伪造回执或直接启动 writer。

本记录不包含凭据、业务数据或受保护接口响应。
