# 国金 QMT 主动快照采集

本次继续使用已授权的完整版国金 QMT。实时行情改为官方
`ContextInfo.get_full_tick` 主动读取，移除 `subscribe_whole_quote` 行情回调路径。
不要求 MiniQMT、外部 xtquant 行情服务或新增数据供应商。

## 依据与适用范围

2026-09-18 13:14 的本机 `native_fault.log` 记录了原生 access violation，
Python 栈位于 `_receive_quotes`、订阅 lambda 和 `_PyContextInfo.on_quote_wrapper`。
它证明故障发生时执行了行情回调，不能单凭该栈断言所有历史崩溃都由此引起。

迅投[官方常见问题](https://dict.thinktrader.net/innerApi/question_answer.html)
说明 `get_full_tick` 读取客户端全推缓存，无需订阅。
[行情接口](https://dict.thinktrader.net/innerApi/data_function.html)
定义了返回的原始事件时间和盘口字段。
本地已验证的 `schedule_run` / `cancel_schedule_run` 继续管理单次定时任务，
见[官方定时器](https://dict.thinktrader.net/innerApi/system_function.html)。

轮询产生采样快照，不提供无损逐笔数据。历史日线、分钟线仍由现有独立任务获取，
不从这些快照补造。证券目录、原生昨收认证、数据库结构和任务归属不变。

## 采集与真实性

- 一个可取消的定时任务串行执行有限批次的原生请求；上一轮结束后才安排下一轮。
- 每次最多读取 2,000 个代码，重点证券优先，全市场连续分批轮转。
  5,563 股、280 个重点代码时，每 4 轮完成一份全市场快照；只发布完整扫描结果。
  继续执行原有 15 秒行情新鲜度门槛，实际原生调用或其他任务延迟仍会触发阻断。
- 行情保留原生事件时间；观察时间记录真实读取。重复的相同缓存行情不能刷新其观察时间。
- 新协议为 `probiga.qmt-full-tick-poll.v1`，采集模式为 `full_tick_poll`。
  接收端拒绝旧回调协议，不以文件刚更新替代行情新鲜度。
- 实时入库继续检查事件日期、交易时段、采集延迟和未来时间。停牌或未更新行情不能
  通过刷新心跳取得实时资格。数据库中的 `LIVE_FORWARD` 发布回执仍表示当时实际采集，
  与新采集协议的 `LIVE_SNAPSHOT` 回执是不同概念。
- 停止时取消定时器，拒绝迟到任务；不再保留订阅重连或旧回调处理器。

## 发布边界

分类为跨端。Windows 内置策略、`integrations/bigqmt` 接收端、采集脚本和
健康检查共同改变实时快照协议。必须在同一合并 main 版本下协调两端切换，
不能只替换内置策略文件。标准部署的版本身份、写入围栏和回滚验证继续生效。

上线后分别验证加载的策略身份、轮询计数、完整全市场扫描、实际源时间、入库回执，
并检查 `native_fault.log` 是否出现新故障。盘后短测不能代替完整交易时段的稳定性验证，
也不能证明闭源客户端绝无其他原生故障。
