# 全市场股票日线缺口处置

输入单位为一个交易日、一只证券和一种行情口径。先判定交易日和证券范围，再检查目标日行情，最后为确有缺口的证券核验原因。全市场完成须逐券对齐目录、正式行和完成回执。

| 情形 | 判定依据 | 处置及验收 |
|---|---|---|
| 节假日、临时休市、时区跨日或请求日期有误 | 交易所日历、北京时间、任务目标日期 | 休市日无交易分区；日期错误应纠正请求。用错日期的行情不能补目标日。 |
| 尚未收盘或收盘文件还在更新 | 交易时段、来源生成时间、目标日终态 | 等待当日既定发布时点，复用已落盘数据。收盘前的快照不能证明全天无成交。 |
| ETF、指数、债券、非 A 股混入；市场后缀错误；同一证券重复或代码被重新使用 | 证券类型、交易所、完整代码、有效期和独立证券目录 | 按历史身份确定范围，按已验证的同一身份去重。类型、交易所或日期有冲突时保留待核。 |
| 新股已分配代码，仍在询价、申购、摇号、缴款，或上市日为空、是占位值 | 发行人正式披露、证券代码、公开日期、能明确约束目标日的发行日程 | 仅在证据有效区间归为尚未上市，保存公告文本和哈希。缴款期限之后到实际挂牌之前须另取有效证据。延期、暂缓或取消发行同样要核实生效范围。 |
| 上市日已公告；上市首日、重新上市、转板或换代码 | 明确上市日期的正式公告、当时证券身份和目标日真实成交 | 上市前可认定无行情；上市首日重新要求成交或当日无交易证明。首日、除权日和代码变更须核对原生昨收或适用的参考价。 |
| 正常交易、涨停、跌停、一字板、ST 或风险警示 | 当日原生开高低收、昨收、量额、证券状态 | 有合法成交即保留。交易限制进入回测成交模型；不能仅凭价格不动或风险警示标签判为停牌。 |
| 全天停牌、重大事项停牌、合并换股停牌 | 同证券同交易日的原生停牌状态和零成交证据，或符合既有规则的正式停牌公告与来源响应 | 登记全天无成交并保留证据；复牌日重新核验。公告窗口确已查询且无匹配事项，本身不构成停牌证明。 |
| 盘中临停、盘中复牌、全天零成交但无停牌证明 | 带时点的状态和真实成交；全天停牌依据只在其生效区间有效 | 保留实际发生的成交。对无成交且身份未决的个股单独补查，不能依据盘口空、价量为零或昨收相同作结论。 |
| 退市整理、最后交易日、终止上市、吸收合并、退市后转入其他市场 | 正式生效日期、交易所、代码、停复牌及摘牌文件 | 整理期和最后交易日仍验证实际行情；按正式停牌或摘牌依据划定无交易范围。旧市场和新市场分别处理。 |
| 单只证券缺文件、缺目标日、客户端缓存滞后；供应商超时、权限不足、网络或接口变更 | 当日证券目录、独立来源、请求结果、数据时间和接收时间 | 使用既有补采和口径兼容的来源；保留证券缺口。外部调用失败不能转成合法无行情。 |
| 单只原始文件损坏、记录重复、OHLC 矛盾、昨收异常；价格单位、成交量单位、复权或金额精度有误 | 文件结构、证券和交易日、口径、价格区间、原生字段和独立核对 | 隔离问题记录；保留其余已验证证券；用正确源恢复或执行有前后值证据的正式修订。禁止用旧值、零值补齐。 |
| 缓存全空、整批日期错误、大面积缺文件、目录或日历缺失、行情来自错误市场 | 全量源清单、当日 A 股子集、目标日实有记录数、目录与日历身份 | 优先修共同来源并停止批量逐券查询；独立日期和无关数据集继续。不能按成功比例签发全市场完成。 |
| 来源彼此矛盾；同日多个版本；发布后盘后大宗成交或金额修订 | 版本、原始行、成交所处市场和时间、受控修订证据 | 先确认权威版本；修订绑定原完成记录并核对差异。两端须能复验同一证据，保留历史可用时间。 |
| 写库超时、唯一键冲突、并发采集、进程退出、重复发布、回执缺失或与正式行不一致 | 日期与来源互斥、事务、已写记录数和内容哈希、既有完成回执、业务断点 | 未提交事务回滚，复用已验证数据；恢复前核对原任务租约和写入结果。只有正式数据与回执一致后才解锁依赖全市场的任务。 |
| 日线已完成，分钟线、资金流、策略评分快照或公告仍缺 | 各数据集自身的覆盖、时效、完成回执和读回 | 日线仅证明日线。分别恢复相关分区；回测使用决策时真实可用的证券、数据及版本。 |
| 新类型或现有来源无法给出结论 | 未能吻合已验证交易、合法无交易或范围外任一情形 | 记录目标日期、证券、失败环节及已取得的证据，保持未决。新增规则须能用真实来源复验。 |

## 有缺口时哪些工作可以继续

已确认交易的证券保存当天通过校验的行情。已证实尚未上市、全天停牌或终止上市的证券保存具体依据，不生成日线。没有证据的证券单列日期、代码和原因。在当天至少有一条有效行情、且目录和日历可核实时，普通日线采集会把已验证的记录与逐券缺口保存为 `stock_daily_attempt` 断点。重试重新检查变化的原生记录，继续补缺口。未决期间，依赖整日覆盖的排名、股票池和回测继续等待，其他交易日和独立数据集按各自的要求处理。

个股详情和持仓列表的盘后报价可以从断点读取指定证券已核验的日线。页面标明行情日期、来源和核验时间。未决、停牌、尚未上市的证券无法从该断点取出价格。该展示使用独立字段，策略、成交模型及持仓决策继续遵循各自原有的数据准入条件。

验收同一交易日有两个等式。采集中，目录内应核验数等于已验证交易数、已有凭证的无行情数和未决数之和。发布时，未决数必须为零，正式日线行数必须等于已验证交易证券数。两个等式之外还须检查各组身份互斥、每只证券的来源和正式回执的内容哈希，避免重复和错码相互抵消。

## 11 月 27 日新股实例

猎奇智能（301661）的目录上市日为占位值。发行人公告载明 2026 年 11 月 26 日申购、27 日摇号、30 日缴款。该文件能证明 27 日尚处于首次发行阶段。行情系统应核验该证券的有限日期范围，日线和分钟线不产生交易记录；仍应采集该证券已经公开的发行公告。[发行人原始公告，第 34 页](https://static.cninfo.com.cn/finalpage/2026-11-25/1225685486.PDF#page=34)

青海春天（600381）同日全天停牌。巨潮的索引标题只写了撤销风险警示，发行人公告正文明确写明 27 日停牌一天、30 日复牌。采集器会查阅这类公告，逐项核对证券代码、日期、整日停牌表述与 QMT 当日零成交快照。仅有风险警示或撤销申请时，仍须核验实际交易状态。[青海春天公告](https://static.cninfo.com.cn/finalpage/2026-11-27/1225690996.PDF)

验收时对同一日逐项读回目录内证券数量、真实交易证券及日线数、按原因分类的合法无行情证券、仍待核验的证券、正式回执与内容哈希。然后分别核对分钟线和资金流的实际交易证券范围，以及策略评分的真实发布时间。代码已上线、接口健康或调度器已接单均只能证明其自身阶段。
