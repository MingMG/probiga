## 3. 本轮源头修复

1. 纠正历史库路由：股票/指数日 K 与分钟数据现在写入 API 实际读取的 `KLINE_MYSQL_URL`/`MINUTE_MYSQL_URL` 目标，不再出现“任务成功但页面读到旧库”的假成功。
2. 全量任务采用分批安全替换：单批失败不删除旧数据；只有完整全市场任务通过覆盖校验后，才清理目标交易日的过期代码和异常时间边界。
3. 实时股票与指数快照采用 staging/事务原子替换；空结果、低覆盖和异常价格直接失败并保留上一份快照。
4. 股票分钟统一 240 根标准，处理 09:30 集合竞价、午休边界、停牌零成交和重复键；盘中 `count=20` 增量绝不误删完整交易日。
5. 指数/概念成分统一经过证券类型、六位代码和当前基础股票池三层过滤；目录与成分同时提交，避免半张新表配半张旧表。
6. 股票分钟价格与分钟资金流拆成独立任务、独立健康校验；分钟资金流新增夜间全股票池任务，使用完整临时表，覆盖不足不提交。
7. 生产调度补齐 QMT 股票池、指数池、指数成分、概念目录/成分、指数日 K、指数分钟任务；不可靠的旧 QMT 概念分钟/K 线任务保持停用。
8. QMT 网关只通过 `127.0.0.1:18765` 反向隧道暴露，历史请求设置超时、批大小和资源上限；生产 API 与调度器继续使用独立进程和数据库连接池。
9. QMT 网关对 Unicode 解码、HTTP 断连、Windows Socket 10053/10054/10060/10061 和 `isNetError` 做最多 3 次有限退避重试；权限、参数等确定性错误不重试。
10. Windows 端新增不依赖 WMI 的 QMT 客户端独立守护，10 秒检查一次并用命名互斥量保证单实例；受控终止客户端后已自动重启并恢复实际行情取数，登录凭据不写入文件、命令行或日志。
11. 股票池新增北交所 810 代码段过滤。[北交所证券代码、证券简称编制指引](https://www.bse.cn/uploads/6/file/public/202404/20240419121551_vhsa4vwi0q.pdf)将 810 定义为向特定对象发行可转换公司债券；本轮发现的 3 只“定转”不再被误当成 A 股，也不再造成日 K、分钟价和分钟资金流的虚假缺口。

## 6. 内存与速度结论

生产服务器约 3.5GB 内存。QMT 全量分钟任务设置 `MemoryHigh=450MB`、`MemoryMax=750MB`，实际长期稳定在约 172–177MB；最终股票日 K 约 157MB，外部分钟资金流约 89MB，空闲时生产调度器约 59MB。任务运行时服务器仍保留约 1.85–2.1GB 可用内存且 Swap 为 0。任务没有继续申请内存，CPU 使用也远低于配额；实测扩大 QMT 批大小和数据库写块并未提高吞吐。当前瓶颈是单 QMT 终端历史接口在网关锁内串行返回，不是内存不足，因此继续加内存不会提速，反而会减少 API/MySQL 的故障余量。保留现有资源上限是本机 3.5GB 配置下更稳妥的生产参数。
