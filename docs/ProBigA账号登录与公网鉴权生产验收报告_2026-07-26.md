## 1. 本次实现

1. 新增独立登录页 `/login`。
2. 无管理员账号时，只允许创建第一个账号；该账号自动成为 `ADMIN`。
3. 第一个账号创建成功后，注册入口立即关闭，不能通过重复注册获得权限。
4. 首账号公网注册不是永久开放，当前生产窗口截止：

   ```text
   2026-07-26 21:00:00 +08:00
   ```

5. 密码使用 `PBKDF2-HMAC-SHA256`、随机盐和60万次迭代保存，数据库不保存明文密码。
6. 登录后签发随机不透明会话令牌；数据库只保存令牌的 SHA-256 摘要。
7. 会话有效期24小时，第20小时开始自动轮换令牌。页面未在到期前打开时，需要重新登录。
8. 会话 Cookie 使用 `HttpOnly`、`SameSite=Strict`，前端不再把长期管理员令牌写入 `localStorage`。
9. 连续登录失败5次后，账号锁定15分钟。
10. 注册、登录、失败、刷新和退出均写入鉴权审计表。
11. Cookie 写操作增加同源校验，拒绝跨站操作请求。
12. 原管理员令牌仍保留给生产脚本和运维自动化，不暴露给浏览器页面。
13. 所有业务页面和业务 API 统一鉴权，仅保留 `/api/auth/*` 与 `/api/health/*` 为公开入口。
14. 增加 `nosniff`、禁止 iframe、同源 Referrer 和浏览器权限限制等响应头。
15. Nginx 原先直接返回的 `/static/*.html` 旧入口已改为先经过应用鉴权，不再能绕过服务端跳转。

## 7. 仍未完成：HTTPS

生产当前只有 HTTP 80端口，没有域名和 TLS 证书。账号鉴权已经解决了“任何公网访问者都能直接操作”的问题，但 HTTP 不能防止网络链路上的窃听或篡改：

- 登录密码在传输过程中没有 TLS 加密；
- 会话 Cookie 在传输过程中没有 TLS 加密；
- 不适合在公共 Wi-Fi 或不可信网络下登录。

登录页已明确显示该警告，生产 Cookie 的 `Secure` 属性暂时不能开启。后续绑定域名并启用 HTTPS 后，应将：

```text
PROBIGA_AUTH_COOKIE_SECURE=true
```

在 HTTPS 完成前，账号登录功能可用于访问控制，但不能宣称公网传输安全已经完整通过。
