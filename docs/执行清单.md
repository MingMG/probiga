## 脚本总索引（新增脚本请同步维护本节）

| 命令 | 脚本路径 | 作用 |
|------|----------|------|
| `python -m biz.stock_info.sync_stock_info` | `biz\stock_info\sync_stock_info.py` | STOCK-INFO 全量同步 → MySQL `probiga` 多张 `si_*` 表（默认先 TRUNCATE 全部 14 张表） |

| `python -m biz.stock_info.sync_all_code_incremental` | `biz\stock_info\sync_all_code_incremental.py` | 仅表 `si_all_code` 增量 upsert（不 TRUNCATE） |
| `python -m biz.notice.sync_notice_em …` | `biz\notice\sync_notice_em.py` | 东财个股公告标题入库 → 表 `si_notice_eastmoney`（`--stock` 或 `--from-si-all-code`；需网络，见 `--sleep`） |
| `python -m biz.sentiment.sync_sentiment` | `biz\sentiment\sync_sentiment.py` | 舆情 SENTIMENT → MySQL `probiga` 多张 `st_*` 表（各步写入前 TRUNCATE 本表；可选 `SE_SKIP_GLOBAL_TRUNCATE=1`） |
| `python -m biz.stock_market.sync_stock_market` | `biz\stock_market\sync_stock_market.py` | STOCK-MARKET 文档接口 → MySQL `probiga` 多张 `sm_*` 表（全部含自增 `id`；支持 `--only` 分步） |
| `python -m biz.stock_market.realtime_quotes …` | `biz\stock_market\realtime_quotes.py` | 指定代码多股最新价快照（新浪）；可选 `--csv` / `--mysql` |
| `python -m uvicorn server.api.main:app …` | `server\api\main.py` | FastAPI 平台接口（健康检查、企微联调等） |
| `python -m strategies.runner` | `strategies\runner.py` | 策略入口占位 |

## 步骤 3：STOCK-INFO 数据同步到 MySQL

**作用**：拉取 `adata.stock.info` 相关接口数据，写入库 `probiga`（表结构见 `biz\stock_info\sql\01_si_stock_info_tables.sql`）。

**前置**：本机 MySQL 已启动，已创建用户/库（或脚本内 DDL 会自动建库 `probiga`）。

**执行（默认：清空 14 张表后全量写入）**：

```powershell
cd "e:\My Code\ProBigA"
python -m biz.stock_info.sync_stock_info
```

**执行（你已只有 `si_all_code` 有数据：保留代码表，把其余表接上）**：

```powershell
cd "e:\My Code\ProBigA"
$env:SI_SKIP_DDL="1"
$env:SI_SKIP_GLOBAL_TRUNCATE="1"
$env:SI_SYNC_SKIP_ALL_CODE="1"
$env:SI_CONTINUE_WITHOUT_INDEX="1"
python -m biz.stock_info.sync_stock_info
```

说明：`SI_SYNC_SKIP_ALL_CODE=1` 时不再请求 `all_code()`，从库里读 `si_all_code` 做个股类同步；其它步骤在写入前会**单独 TRUNCATE 各自目标表**，不会动 `si_all_code`。某一步若仍失败（如东财断连），会**打日志并继续后面步骤**，多跑几次或调大 `SI_REQUEST_SLEEP` 可逐步补全。

**常用环境变量**（PowerShell 示例，同一行里设置仅对本次命令生效）：

```powershell
$env:MYSQL_URL="<从受控环境加载 MYSQL_URL>"
$env:SI_REQUEST_SLEEP="0.2"
$env:SI_YEAR_START="2010"
$env:SI_YEAR_END="2027"
$env:SI_MAX_STOCKS="0"
$env:SI_SKIP_DDL="0"
$env:SI_INCLUDE_THS_NAME="0"
$env:SI_HTTP_RETRIES="8"
$env:SI_HTTP_BACKOFF="3"
python -m biz.stock_info.sync_stock_info
```

说明：`SI_MAX_STOCKS` 大于 0 时只处理前 N 只股票（调试用）；`SI_SKIP_DDL=1` 表示表已建好、跳过执行 DDL；`SI_INCLUDE_THS_NAME=1` 会按概念名称拉同花顺成分（请求多、易风控）。若遇数据源断连（`RemoteDisconnected`），脚本会对 HTTP 自动重试，仍失败时可加大 `SI_REQUEST_SLEEP`、`SI_HTTP_BACKOFF` 后再跑。

**仅股票代码表 `si_all_code` 增量（不 TRUNCATE、按代码 upsert）**：

```powershell
cd "e:\My Code\ProBigA"
python -m biz.stock_info.sync_all_code_incremental
```

适合每日/定时跑，合并新股与简称、上市日期等变更。其它 `si_*` 表仍以全量脚本为准；若也要增量需按表单独设计（如按 `snapshot_at`、按交易日分区等）。

**若报错在「指数列表」一步**（栈里有 `sync_all_index_code`、`stock_index.py`、`push2.eastmoney`）：这是东财接口问题，不是你的库。可加大 `SI_COOLDOWN_BEFORE_INDEX`（默认约 10 秒）；脚本会自动走备用域名 + 浏览器头（`SI_INDEX_FALLBACK=1`）；仍不行时默认 `SI_CONTINUE_WITHOUT_INDEX=1` 会跳过 `si_all_index_code` / `si_index_constituent`，继续同步后面表。

## 步骤 3b：舆情（SENTIMENT）同步到 MySQL

**作用**：拉取 `adata.sentiment` 文档中的解禁、融资融券、北向、人气榜、龙虎榜、扫雷等接口，写入库 `probiga`（表结构见 `biz\sentiment\sql\01_sentiment_tables.sql`）。

**前置**：已安装依赖（步骤 1）；MySQL 可用；**首次**需建表：不要带 `SE_SKIP_DDL=1`，或先手工执行上述 SQL 文件。

**执行（默认：开场清空全部 `st_*` 舆情表，再按步拉取写入）**：

```powershell
cd "e:\My Code\ProBigA"
python -m biz.sentiment.sync_sentiment
```

**按步骤单独执行（推荐你这种「一次只刷一类」）**：

```powershell
cd "e:\My Code\ProBigA"
python -m biz.sentiment.sync_sentiment --only hot_concept
python -m biz.sentiment.sync_sentiment --only a_list_daily
python -m biz.sentiment.sync_sentiment --only a_list_info
python -m biz.sentiment.sync_sentiment --only hot_east,hot_ths
```

`--only` 可选值：`lifting`、`margin`、`north_daily`、`north_min`、`north_current`、`hot_east`、`hot_ths`、`hot_concept`、`a_list_daily`、`a_list_info`、`mine`。  
说明：`--only a_list_info` 时会先拉当天龙虎榜日列表，用于生成单股明细股票池。

**仅重拉数据、表已建好**（与 STOCK-INFO 的「补表」思路类似：不开场清空全部表，各步骤仍会 `TRUNCATE` 本步目标表）：

```powershell
cd "e:\My Code\ProBigA"
$env:SE_SKIP_DDL="1"
$env:SE_SKIP_GLOBAL_TRUNCATE="1"
python -m biz.sentiment.sync_sentiment
```

**常用环境变量**（PowerShell 示例）：

```powershell
$env:MYSQL_URL="<从受控环境加载 MYSQL_URL>"
$env:SE_MARGIN_START="2020-01-01"
$env:SE_NORTH_START="2017-01-01"
$env:SE_A_LIST_DATE="2024-07-04"
$env:SE_MAX_STOCKS="300"
$env:SE_SKIP_MINE="0"
$env:SE_A_LIST_INFO="0"
$env:SE_A_LIST_INFO_MAX="80"
python -m biz.sentiment.sync_sentiment
```

说明：`SE_MAX_STOCKS` 控制扫雷遍历 `si_all_code` 的数量（默认 300）；`0` 表示不限制（请求量极大）。单股龙虎榜明细默认执行（`SE_A_LIST_INFO=1`）；若你要跳过，显式设 `SE_A_LIST_INFO=0`。HTTP 重试可与 STOCK-INFO 共用 `SI_HTTP_RETRIES` / `SI_HTTP_BACKOFF`，或单独设 `SE_HTTP_*`。单步失败会打日志并继续后续步骤。

## 步骤 3c：STOCK-MARKET 文档接口同步到 MySQL

**作用**：对接 `接口文档股票-STOCK-MARKET`，将股票行情、五档、成交、资金流、概念行情、指数行情等写入 `sm_*` 表（见 `biz\stock_market\sql\02_sm_stock_market_tables.sql`）。  
**约束已落实**：新建 `sm_*` 表均带 `id BIGINT AUTO_INCREMENT` 主键。

**执行（全量步骤）**：

```powershell
cd "e:\My Code\ProBigA"
python -m biz.stock_market.sync_stock_market
```

**按步骤单独执行（推荐）**：

```powershell
cd "e:\My Code\ProBigA"
python -m biz.stock_market.sync_stock_market --only stock_current
python -m biz.stock_market.sync_stock_market --only stock_kline
python -m biz.stock_market.sync_stock_market --only stock_kline,index_kline,concept_ths_kline,concept_east_kline --kline-today
python -m biz.stock_market.sync_stock_market --only stock_kline,index_kline --kline-start 2024-01-01 --kline-end 2024-12-31
python -m biz.stock_market.sync_stock_market --only concept_flow_east
python -m biz.stock_market.sync_stock_market --only index_current
```

`--only` 可选值：`dividend`、`stock_kline`、`stock_minute`、`stock_current`、`stock_five`、`stock_bar`、`stock_flow_min`、`stock_flow_daily`、`concept_ths_kline`、`concept_ths_minute`、`concept_ths_current`、`concept_east_kline`、`concept_east_minute`、`concept_east_current`、`concept_flow_east`、`index_kline`、`index_minute`、`index_current`。

**常用环境变量**：

```powershell
$env:MYSQL_URL="<从受控环境加载 MYSQL_URL>"
$env:SM_SKIP_DDL="0"
$env:SM_SKIP_GLOBAL_TRUNCATE="1"
$env:SM_MAX_STOCKS="200"
$env:SM_MAX_INDEXES="50"
$env:SM_MAX_CONCEPTS="50"
$env:SM_MARKET_START="2020-01-01"
$env:SM_INDEX_START="2020-01-01"
$env:SM_REQUEST_SLEEP="0.2"
python -m biz.stock_market.sync_stock_market --only stock_current
```

说明：脚本默认从 `si_all_code` / `si_all_index_code` / `si_concept_code_*` 读取股票与指数代码池；若这些基础表为空，对应步骤会无数据。为降低请求量，默认数量上限可通过 `SM_MAX_*` 调整。
K 线默认从 2020 开始；可用 `--kline-today` 做收盘后“只补当天”，也可用 `--kline-start/--kline-end` 做任意日期区间补跑。

## 步骤 4b：A 股多股最新价（实时快照，建议盘中验证）

不经过 ``adata.stock.market`` 整包，直接请求新浪行情接口，避免本机 Python 3.14 等与 ``py_mini_racer`` 的兼容问题。

