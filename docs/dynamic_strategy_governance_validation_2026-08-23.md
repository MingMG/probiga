# 动态策略治理系统实施与验证记录（2026-08-23）

## 结论

动态策略治理、策略/组合排名、三级票池、中文生命周期、每日市场路由、动态资金竞争、证据化淘汰与恢复、可新增策略适配器、治理审计和生产发布边界已经按 `dynamic_strategy_governance_v1.md` 落地到当前工作分支。

本次只完成代码、离线测试和本地页面验收，没有连接或修改生产服务器、生产数据库、券商或真实交易通道。所有治理结果均保持 `automatic_real_order_submission=false` 和 `real_order_authority=false`。

系统通过扣费后净期望、利润因子、盈亏比、成本压力、回撤、样本量、Walk-Forward 和证据新鲜度提高“有正期望”的可验证性，但不能保证未来一定盈利。没有合格策略时，正确结果是保持现金，不是强制选票。

## 已实施能力

### 生命周期和理由

页面展示中文状态，英文枚举仅作为内部稳定协议：

| 内部枚举 | 页面名称 | 资金含义 |
|---|---|---|
| `ACTIVE` | 正常运行 | 通过全部准入后按竞争结果获得模拟资金 |
| `REDUCE` | 降权运行 | 保留排名，生命周期风险乘数为 0.5，折减部分留在现金 |
| `SHADOW` | 影子观察 | 只积累独立前向证据，不取得模拟资金资格 |
| `SUSPENDED` | 暂停使用 | 停止授资；恢复时必须先回到影子观察 |
| `RETIRED` | 已淘汰 | 当前版本终态；只能注册新版本重新验证 |

每次新增、版本变化、证据提交/复核、升级、降权、暂停、恢复、淘汰、每日运行和失败阻断都写入仅追加审计，并保存前后状态、中文理由、证据身份和决定哈希。状态不能无理由变化。

### 正期望硬门槛

60/120 个权威交易日资金准入至少要求：

- 已完成交易不少于 80 笔、覆盖不少于 60 个权威交易日；
- 扣除真实费用后的净期望严格为正，毛期望至少覆盖 3 倍估计成本；
- 盈亏比不低于 1.10，利润因子不低于 1.30；
- 1.5 倍成本压力后期望仍严格为正；
- 最大回撤不高于 12%，最好 5 笔利润贡献不高于 70%；
- 5 段 Walk-Forward 至少 4 段为正；
- 连续 3 次独立证据更新通过，证据最长 7 天未过期。

20 个权威交易日衰减门要求至少 20 笔、完整覆盖 20 日、扣费后净期望严格为正、利润因子严格大于 1.00，并且 1.5 倍真实成本压力后仍严格为正。失败会降权、进入影子或暂停；不会继续死拿。

### 动态策略、组合和每日更新

- 策略数量不固定。新策略通过版本化注册表和代码所有的执行适配器清单加入，不需要修改固定数量常量。
- 策略公式、参数、成本模型或适配器变化时生成不可变新版本，从影子观察重新验证，不能覆盖旧证据。
- 每日重算市场状态、策略路由、20/60/120 日健康度、衰减、票池、组合约束和资金权重。
- 启用且非暂停/淘汰的动态策略，无论处于正常、降权或影子状态，都必须提交版本、输入、输出、成本模型绑定的有效 CandidateBatch 回执；缺失即整轮失败关闭。
- 策略和组合使用固定独立赛道排名，组合资金再按成员袖套分解；类型间不使用不可比的原始分数互相挤占。
- 市场风险上限为：趋势上涨 85%、高波动震荡 50%、风险下降 20%、极端事件 0%；未使用预算始终保留现金。

### 排名和票池页面

默认页面的策略排名、组合排名、资金分配和三级票池只读取同一份 canonical governance 快照：

- 观察池；
- 等待确认池；
- 模拟可交易池。

实时 overview 仅保留在默认关闭的“研究输入诊断（非规范结果）”区域。即使实时 overview 出现股票 A，只要 canonical 票池为空，正式页面就不会显示 A。canonical 票池不再静默截断 100 条；101 条及以上会完整显示并标注总条数。

## 一致性和失败关闭

- 每日治理读取目标交易日全部底层候选，`source_row_count` 必须精确等于 `loaded_row_count`，并绑定完整明细哈希；兼容参数 `limit` 不再截断权威输入。
- 当日行业历史必须先完成只追加冻结；失败时不写治理结果并保持现金。
- canonical 读取会重新计算候选集合、票池、市场路由、生命周期计划、资金袖套、现金守恒、风险上限和最终决策哈希；字段漂移或伪造真实下单权限会被拒绝。
- 资金分配使用基点级最大余数法复算，总和必须精确为 100%，仅允许一个现金行，非现金资金不得超过市场风险上限。
- API、每日任务和健康检查在访问数据库或启动后台任务前先验证并封印动态适配器注册表。

## 发布与恢复边界

- 生产依赖锁的 `BLOCKED` 检查位于锁、缓存和 Git 网络副作用之前。
- API、scheduler、AI writer 均绑定 release SHA、release tree SHA 和 adapter registry seal SHA。
- activation journal 持久保存 writer 状态、旧/新治理任务快照、旧/新发布身份、待发布回执及各自 SHA-256。
- 中断恢复逐一验证 API、scheduler 和 AI writer；不能因 API inactive 提前跳过其他 writer。
- `DEPLOYED` 回执只在新运行时完整验证、journal 标记 finalized 后发布；中断后可以幂等补写。
- Windows/Git Bash 测试不再执行会污染 pytest 宿主的真实 `SIGKILL`，而是构造相同的持久 mixed-unit 状态；Linux/POSIX 生产 CI 仍执行真实 `SIGKILL` 并验证恢复。
