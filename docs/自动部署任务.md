# ProBigA 提交后自动部署任务

这个任务用于本地手动 `git commit` 成功后自动部署。

默认模式是：

1. 你手动修改代码并执行 `git commit`。
2. 本地 `post-commit` hook 自动执行 `git push origin main`。
3. GitHub Actions 里的 `.github/workflows/deploy.yml` 在 `main` 分支收到 push 后运行完整 CI；只有生产部署开关和 SSH 身份均已配置时才部署到服务器。

## 生产部署开关与 SSH 身份

生产部署采用 fail-closed 模式。仓库级 Actions 变量
`PRODUCTION_DEPLOY_ENABLED` 必须精确等于 `true`，`deploy` 作业才会启动。变量缺失、
值不为 `true` 或仍在迁移生产 SSH 身份时，CI 测试照常运行，部署作业显示为 skipped，
不会把“未配置生产凭据”反复报告成失败部署。工作流同时会显示成功的
`Production deployment disabled` 作业，并在摘要中明确标记本次未部署。

开启前需要在 GitHub 的 `production` Environment secrets 中配置并验证：

- `SERVER_HOST`：生产 ECS 地址；
- `SERVER_USER`：非 `root` 的专用部署账号；
- `SSH_PRIVATE_KEY`：该部署账号对应的完整私钥；
- `SERVER_HOST_FINGERPRINT`：带外核验的 SSH 主机指纹，格式为 `SHA256:` 加 43 个 Base64 字符。

服务器还必须满足部署脚本的安全前置条件，包括：服务以非 `root` 账号运行、部署账号
具有脚本所需的受限 `sudo` 权限，以及 `/usr/bin/python3.14` 可用。完成服务器迁移并用
手动验证后，再在仓库 `Settings > Secrets and variables > Actions > Variables` 中把
`PRODUCTION_DEPLOY_ENABLED` 设置为 `true`。这个开关必须是仓库级变量，因为 job 的
`if` 在 runner 取得 Environment 变量之前求值。不要通过删除身份校验或改回共享 root
密码来开启部署。

## 安装

在仓库根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\install_post_commit_deploy.ps1
```

安装脚本会设置本仓库的本地 Git 配置：

```powershell
git config core.hooksPath tools/git-hooks
git config probiga.postCommitDeploy.enabled true
git config probiga.postCommitDeploy.mode push
git config probiga.postCommitDeploy.branch main
git config probiga.postCommitDeploy.remote origin
```

## 使用

正常提交即可：

```powershell
git add .
git commit -m "your message"
```

提交成功后 hook 会自动 push，随后 GitHub Actions 运行 CI。只有
`PRODUCTION_DEPLOY_ENABLED=true` 时才会自动部署。

## 切换为本地部署

如果想提交后直接在本机调用 `deploy/deploy.ps1`，执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\install_post_commit_deploy.ps1 -Mode local
```

本地部署模式会走 SSH/SCP，要求本机已经能访问服务器。

## 暂停自动部署

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\install_post_commit_deploy.ps1 -Disable
```

重新启用：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\install_post_commit_deploy.ps1
```
