# 盘中关键节点播报

盘中播报不是按固定时刻写小作文，而是每分钟检查一次新行情快照，只在事件状态发生变化时生成消息。默认以 `shadow` 模式上线：完整计算、落库并生成拟推送正文，但不发送企业微信；通过影子验收后再显式切换为 `live`。

## 事件范围

- 全市场：弱转稳、修复扩散、普涨确认、转弱和风险加速。
- 板块：从单核拉升转为多股扩散、放量退潮、核心与后排共振。
- 个股：成交核心启动、炸板/跳水、关键股带动或拖累板块；优先覆盖持仓、自选、板块龙头和成交额前列。
- 风格：大盘/小盘、科技/红利等互斥篮子的相对切换与跷跷板反转。
- 宽基：多只宽基 ETF 放量、对应指数止跌而全市场广度暂未跟随的“托底形态”。

每条消息固定包含可复核事实、带边界的判断、升级条件和失效条件，并附数据截止时间、覆盖率与来源。行情只能支持“疑似宽基资金托底”或“托底形态确认，资金身份未知”；没有官方披露时不得写成“国家队确认进场”。盘口或逐笔数据不完整时，也不得把成交放大描述为主动买入。

## 数据和质量门

全市场事实只读取国金 QMT 原子快照及其质量回执。目标批次必须是当日 `LIVE_FORWARD`、质量 `PASS`、覆盖率不低于 95%，源时刻在允许延迟内，且股票明细数量与回执相符。任一硬门失败时不判断、不推送。

行业使用最近一份 `QMT_VALIDATED` 的不可变申万一级成员快照，并核对运行凭据中的关系数。行业数据不可用时只降级板块段，不虚构板块结论。指数与 ETF 使用独立的小型基准采样；历史同刻样本不足时只报告“当日近几分钟成交加速”，积累足够交易日后才允许给出历史同期倍数。

## 状态、去重和发送

事件经历 `SUSPECTED → ENHANCED → CONFIRMED → INVALIDATED`。疑似状态只落库；增强、确认、失效各最多发送一次。持续同一事件不重复推送，状态升级和明确失效可以绕过普通冷却。状态、证据、原始观察和待发送消息均持久化，调度器或进程重启后不会把旧事件重新发送。

企业微信地址只通过环境变量 `WECOM_INTRADAY_WEBHOOK_URL` 注入，不进入源码、任务参数、数据库证据或日志。发送复用带分段、回执、错误码检查和脱敏的统一投递器；缺配置、非零 `errcode`、超时或部分分段失败都会使任务非零退出并按退避策略重试。

## 启用

首次安装任务时显式运行：

```bash
python tools/ensure_quality_gate.py --intraday-alert-only --mode shadow
python tools/ensure_quality_gate.py --validate-intraday-alert --expected-mode shadow
```

影子模式至少覆盖完整交易日并审阅误报、漏报、数据中断和午休恢复。通过后显式切换：

```bash
python tools/ensure_quality_gate.py --intraday-alert-only --mode live
python tools/ensure_quality_gate.py --validate-intraday-alert --expected-mode live
```

调度任务为 Linux 所有、每分钟触发，并使用独立单槽 lane。脚本自身再次严格检查交易日以及 `09:30–11:30`、`13:00–15:00`；日历未知时失败关闭，午休不累计连续命中。
