## 0. 可行性审查结论

### 0.1 总结论

本方案的工程方向可行，但“基础设施可实现”不等于“股票预测已经具有稳定正收益”。截至 2026-08-03，现有股票模型仍没有通过正式 OOS 和前向验收，因此 V4 可以进入数据、审计、状态监测、风险提醒和模拟盘建设，但在通过本文规定的量化门槛前：

- `ACTIONABLE` 生产买入状态必须关闭；
- 只能输出 `RESEARCH`、`WATCH`、`CONDITIONAL`、`HOLD_ONLY`、`EXIT_ALERT` 和模拟盘动作；
- 不得把工程验收、历史案例命中或短期模拟收益表述为模型有效；
- 真实自动下单继续保持数据库和应用双重禁用。

现有 OOS 研究累计检查过 77 个候选搜索，最终结论为 `BLOCK`；未经查看的前向证据从 2026-08-03 起重新累计，当前基线为 0 个交易日、0 笔成熟组合交易。详见[现有 OOS 最终验收](./ProBigA_trading_v4_OOS_final_acceptance_2026-08-01.md)。

### 0.2 可行性分层

| 层级 | 当前结论 | 范围 |
|---|---|---|
| 可直接实施 | 可行 | 统一数据上下文、数据门禁、审计、候选分层、持仓批次/T+1、日线和分钟量价、组合约束、预警状态机、模拟成交 |
| 需降级实施 | 条件可行 | 行业轮动、新闻事件、盘中资金、外围市场；只能使用已有历史覆盖，缺失部分按 `FORWARD_ONLY` 积累 |
| 需先补数据 | 当前不可回测 | 历史五档盘口与撤单、可靠历史行业成分、精确公告首次公开时间、ETF 申赎、分析师一致预期、结构化宏观修订序列 |
| 尚未证明 | 不得承诺 | 稳定正收益的股票预测、准确提前识别每次风格切换、由稀有大事件推导已校准收益概率 |

### 0.4 版本与迁移策略

“V4”是本文的产品能力版本，不要求新建一套与现有系统平行的交易账本。实施采用增量方式：

1. 复用 V3 的预测、假设、目标组合、持仓状态、模型注册、验证和前向证据；
2. 复用 V2 的账户、意图、订单、成交、持仓批次、现金账和真实交易硬闸；
3. 只新增现有模型无法表达的决策上下文、行业状态、事件实体、轮动提醒和持仓重估字段/表；
4. 先以 `trading_v3_dynamic_v4` 影子能力运行，避免与现有 `research_v4` OOS 研究命名混淆；
5. 只有通过完整验收后，才将 `/api/v4` 设为默认读取入口。

## 1. 文档目的

本文档是 ProBigA 动态交易决策系统 V4 的统一需求、设计和验收基线。后续代码设计、数据库迁移、接口开发、调度配置、页面展示、历史回放、模拟盘验证和生产发布均应以本文档为依据。

V4 不再把股票永久划入“短线、趋势、价值、科技、红利”等固定抽屉，也不把已经发生的强势简单等同于未来可买。系统必须基于决策时点已经可获得的事实，持续重估市场、行业、个股和持仓，输出可追溯、可执行、可验证的动态决策。

系统目标不是保证每次预测正确，而是：

1. 在风险扩大前尽可能提前预警；
2. 原始逻辑失效后及时减仓或退出；
3. 资金发生行业迁移时识别轮动；
4. 在机会尚未充分定价时进入观察和确认流程；
5. 使用样本外证据约束模型，禁止凭叙事直接生成买入建议；
6. 将每一次建议与当时事实、后续结果建立完整审计链。

## 2. 核心原则

### 2.1 事实优先

任何决策必须基于明确的数据快照。关键数据缺失、过期、相互冲突或无法交叉核验时，不得输出“可买入”，只能输出“数据不足”或“等待确认”。

### 2.2 时间点正确

训练、历史回放和生产决策只能读取 `available_at <= decision_at` 的数据。公告、财务数据、行业成分、新闻和行情均以当时真实可用时间为准，严禁未来数据泄漏。

### 2.3 动态重估

买入标签只记录信号来源，不决定持有时间。所有持仓在盘后、盘前、盘中持续重新评估。即使最初属于中期趋势，只要趋势、资金、行业或事件逻辑失效，仍应减仓或退出。

### 2.4 预测与执行分离

“值得研究”“进入观察”“满足盘中条件”“可执行买入”是四个不同阶段。系统不得把热点观察标、行业情绪锚点或不可成交涨停股直接展示为普通买入推荐。

### 2.5 概率而非单一标签

市场、行业和个股优先使用多维连续状态和前瞻概率，不使用单一静态分类替代不确定性。尚未经过独立校准的值只能称为“状态分”或“风险分”，不得展示为概率。最终概率必须绑定明确预测契约、可成交样本和独立校准证据。

### 2.6 风险先于评分

停牌、行情失真、数据过期、无法成交、重大合规风险等硬性条件必须在模型评分前处理。可统计风险进入概率和期望计算，不得被高热度或高动量分数无条件覆盖。

### 2.7 防止过度交易

动态不等于频繁反转。换仓必须覆盖手续费、冲击成本、预测误差和 T+1 风险，并通过信号持续性、滞回阈值和冷却时间抑制无效交易。

### 2.8 全程可审计

每条决策必须能回答：使用了什么数据、数据何时可用、触发了哪些因子、模型版本是什么、为什么买卖、何时失效、后来表现如何。

### 2.9 数据故障与市场风险分离

行情冲突、数据源中断或异常值首先触发 `DATA_FEED_FAIL`：停止新增订单、切换可信源并进入只读保护。只有经券商或独立行情确认是真实价格波动后，才能触发市场风险卖出。数据错误本身不得自动生成卖单。

### 2.10 统计有效性与业务解释分离

事件分类、题材归属和文字解释可以帮助用户理解，但只有通过点时回放、样本外检验和前向验收的特征才允许影响 `ACTIONABLE`。语言模型不得单独触发交易动作。

## 3. 系统总体流程

```text
数据采集与时间戳核验
        ↓
重大事件识别、去重与影响传播
        ↓
市场状态概率与风险资产仓位上限
        ↓
行业阶段、资金迁移与轮动概率
        ↓
全市场个股前瞻预测与可执行性过滤
        ↓
当前持仓统一重估与替代机会比较
        ↓
买入 / 持有 / 减仓 / 清仓 / 换仓 / 观察
        ↓
盘中确认、执行约束与预警升级
        ↓
1/3/5/10/20 日前向结果归因与模型校准
```

系统对用户固定输出五张清单：

1. 减仓与退出清单；
2. 行业轮动预警清单；
3. 明日可执行候选清单；
4. 条件观察候选清单；
5. 禁止追入与高风险清单。

## 4. 决策时钟与运行频率

### 4.1 盘后任务

| 时间 | 任务 | 输出 |
|---|---|---|
| 15:10 | 收盘行情、市场宽度、涨跌停结构初算 | 初始市场状态、行业强弱 |
| 16:30 | 已到达的资金、龙虎榜和行业数据补充 | 行业迁移、个股资金特征；迟到源显式标记 |
| 18:30 | 已到达新闻、财报和事件重算 | 事件影响、风险清单的第一版 |
| 20:30 | 公告增量/全量任务完成后的事件重算 | 公告风险修正版；在增量公告源完成前不得宣称实时 |
| 21:30 | 全市场重模型、持仓和组合重估 | 最终次日预案 |
| 次日 08:30 | 隔夜外围、商品、汇率和盘前事件修正 | 盘前版本预案 |

以上时间是目标编排。每个任务按实际上游到达时间启动，不得在数据尚未到达时用旧数据冒充当日数据。任务需以依赖 DAG、数据水位和截止时间驱动，而不是只依赖固定钟点。

```text
日K覆盖与完整性 PASS
→ 市场/行业初算
→ 资金、公告、新闻等各自水位到达或显式超时降级
→ 事件影响与数据质量冻结
→ 最终决策 run
→ 前向证据和反事实队列
```

### 4.2 盘中任务

盘中采用热、温、冷三层，不允许每 5 分钟复制盘后全量重模型：

| 层级 | 范围 | 目标频率 | 允许计算 |
|---|---|---|---|
| 热路径 | 当前持仓、活动订单、T+1 锁定仓、红色预警 | 10 至 60 秒，取决于 QMT 和实测 SLA | 最新价、可卖量、停复牌、涨跌停、可靠盘口代理、立即风险；常驻进程执行 |
| 温路径 | 行业/题材、前 200 至 500 只观察候选 | 3 至 5 分钟 | 增量价格、成交额、宽度、相对强度、事件影响、轻量候选重排 |
| 冷路径 | 约 5,500 只全市场 | 15 至 30 分钟轻扫描；重模型仅盘后或必要事件批量触发 | 预聚合后的轻量特征；禁止扫描 8,000 万行原始分钟表 |

盘中“主力资金”只有在来源、到达延迟和定义已验证时才能使用；第一阶段以成交额变化、上涨宽度、相对强度和可靠分钟资金代理描述，不得把供应商估算值称为真实主力净流入。

| 频率/时间 | 任务 |
|---|---|
| 事件触发 | 一手重大公告、政策、监管、战争、商品异动进入事件队列，仅重算受影响实体；未验证消息只预警 |
| 09:25 | 集合竞价确认 |
| 09:35 | 开盘异常和兑现风险确认 |
| 10:00 | 早盘方向确认 |
| 11:25 | 午前风险快照 |
| 13:30 | 午后资金迁移确认 |
| 14:30 | 尾盘持仓与次日风险评估 |

现有调度器以分钟级子进程任务为主，不能承担 10 秒级热路径。热路径必须使用带心跳、断线恢复、背压、熔断和单实例锁的常驻 worker；分钟级和盘后任务继续使用现有调度器。

### 4.3 A 股交易约束

系统必须显式处理：

- T+1 当日买入不可卖；
- 100 股整数倍；
- 涨跌停和停牌不可成交；
- 一字板、盘口深度不足和封单异常；
- 午间休市；
- 节假日和非交易日；
- 真实手续费、印花税、过户费和冲击成本。

## 5. 统一数据上下文

每次决策必须生成不可变 `DecisionContext`：

| 字段 | 含义 |
|---|---|
| `decision_id` | 决策唯一标识 |
| `decision_at` | 决策发生时间 |
| `trade_date` | 目标交易日 |
| `feature_as_of` | 特征截止交易日 |
| `knowledge_cutoff_at` | 本次决策允许使用的信息最晚可知时间 |
| `market_data_at` | 行情快照时间 |
| `capital_flow_at` | 资金数据时间 |
| `news_cutoff_at` | 新闻截止时间 |
| `announcement_cutoff_at` | 公告截止时间 |
| `external_market_at` | 外围市场数据时间 |
| `is_realtime` | 是否为实时决策 |
| `freshness_status` | PASS/WARN/FAIL |
| `fallback_used` | 是否使用降级数据 |
| `source_manifest_hash` | 引用现有 `st_data_snapshot_v2` 或等价来源清单的哈希 |
| `parent_run_uid` | 盘中增量决策对应的父运行 |
| `source_versions` | 各数据源及版本 |
| `feature_version` | 特征版本 |
| `model_version` | 模型版本 |
| `config_version` | 策略配置版本 |

### 5.1 数据门禁

以下任一条件触发 `FAIL`：

- 关键行情日期落后于预期交易日；
- 实时报价超过允许新鲜度；
- 股票代码、价格或复权口径冲突；
- 公告或财务记录的公开时间不可确定；
- 行业成分使用了决策时点之后的快照；
- 关键特征存在不可解释缺失；
- 多源价格差超过允许阈值。

`FAIL` 时禁止生成新买入。已有持仓仍允许基于可信行情执行保护性风控。

每个数据源需另存独立水位，不得只依赖一个汇总时间：

```text
source_name
event_time
source_published_at
first_seen_at
received_at
revised_at
coverage
latency_ms
quality_status
batch_id
content_hash
```

同一来源的业务发生时间、公开时间、系统首次看到时间和修订时间不可混为一个 `available_at`。

### 5.2 因子可用性门禁

每个因子必须具有以下状态之一：

| 状态 | 含义 | 使用权限 |
|---|---|---|
| `BACKTEST_READY` | 有足够历史、点时语义和覆盖率 | 可进入历史训练和样本外检验 |
| `FORWARD_ONLY` | 从某日开始可靠留存，但无足够历史 | 只能影子采集、展示或前向研究 |
| `DISPLAY_ONLY` | 可解释当前市场，但定义或质量不足 | 只展示，不参与决策评分 |
| `BLOCKED` | 无数据、无授权或质量失败 | 禁止使用，不能填 0 冒充中性 |

因子注册至少保存：

```text
factor_key
factor_role              # GATE / ALPHA / RISK / COST / STATE / EXPLANATION
availability_status
source
history_start
knowledge_time_field
effective_time_field
revision_policy
freshness_sla
coverage_floor
missing_policy
point_in_time_verified
backtest_eligible
feature_set_version
```

因子晋级必须经过数据连续性、时点审计和增量 OOS 验证。因子缺失不自动等于 0；模型需显式携带缺失状态和数据质量。

## 6. 因子体系

所有因子必须登记：名称、定义、方向、数据源、可用时间、更新频率、缺失处理、适用市场状态、衰减方式和样本外有效性。

第 6.1 至 6.12 节是候选因子库，不代表首版全部进入模型。第一版只启用具备点时历史、覆盖充分且经济含义清晰的最小因子集。因子研究遵循：

1. 按价格趋势、量价、行业、事件、基本面、风险和成本分组；
2. 缩放、缺失填充、去极值、相关性筛选只在训练窗口拟合；
3. 同源多周期特征先做按交易日的相关性聚类，避免重复计算同一信息；
4. 每新增一个因子块，必须报告增量 OOS Brier/Log-loss、扣费收益、换手和回撤；
5. 必须做因子块消融、跨窗口稳定性和分布漂移检验；
6. 样本量按有效交易日、独立事件和组合交易计算，不得把同日数千只相关股票当成数千个独立样本；
7. 低频宏观和财务值复制到每只股票、每个盘中快照后，仍只算一个低频信息到达事件；
8. 未产生稳定增量价值的因子保留展示或删除，不以“因子多”作为系统能力指标。

### 6.1 市场环境因子

- 主要指数 1/3/5/10/20/60 日收益；
- 均线结构、斜率和多周期趋势；
- 两市成交额、成交额变化率和持续性；
- 实现波动率、波动率加速度和跳跃风险；
- 上涨/下跌家数比例；
- 创新高/创新低家数；
- 涨停、跌停、触板、炸板数量；
- 封板率、炸板率；
- 最高连板、晋级率和昨日涨停/连板反馈；
- 市场收益集中度；
- 大小盘、成长价值、高低估值相对强弱；
- 市场风险偏好和拥挤度。

### 6.2 宏观与外围因子

- 国内利率、流动性、社融、信贷、M1、M2；
- PMI、CPI、PPI 及预期差；
- 人民币汇率、国债收益率；
- 美联储政策、美债收益率、美元指数；
- 纳斯达克、费城半导体、港股和中概股表现；
- 原油、黄金、铜、铝和相关商品；
- 股指期货升贴水；
- 全球地缘、制裁、航运和供应链风险。

宏观与外围因子必须通过行业敏感度矩阵传导，禁止对所有股票统一加减分。

### 6.3 行业与题材因子

- 行业 1/3/5/10/20 日绝对和相对收益；
- 相对收益一阶、二阶变化；
- 行业成交额占比及变化；
- 资金净流入及连续性；
- 上涨家数、创新高和涨停扩散度；
- 龙头、前排、中位和后排反馈；
- 行业内收益离散度；
- ETF 申赎和成交变化；
- 行业估值分位、拥挤度和景气度；
- 催化新鲜度、意外程度和兑现程度；
- 行业阶段和状态转移概率。

### 6.4 个股价格趋势因子

- 1/3/5/10/20/60 日收益；
- MA5/10/20/60 排列和斜率；
- 距均线、前高和阶段新高距离；
- 突破、回踩、反包、缺口和失败突破；
- 20/60 日回撤；
- 收盘位置和日内振幅；
- 相对行业、指数和全市场强度；
- 趋势稳定性、衰减速度和多周期一致性。

### 6.5 量价与波动因子

- 成交量、成交额、量比和换手率；
- 5/10/20 日成交额变化；
- 放量上涨、放量滞涨、缩量上涨、缩量回调；
- 量价背离；
- ATR 和实现波动率；
- 上下影线、实体和缺口比例；
- 高位放量、波动扩张和跌破放量风险。

### 6.6 实时盘口与资金因子

- 最新价和行情新鲜度；
- VWAP 及价格相对 VWAP；
- 主动买卖金额；
- 大单和超大单流入；
- 委买委卖差、盘口深度和撤单速度；
- 盘口失衡；
- 分时突破、冲高回落和承接；
- 集合竞价涨幅、金额和匹配量；
- 封单金额、封单变化、开板和回封；
- 资金流与价格背离。

### 6.7 涨停、连板与情绪因子

- 是否涨停、连续涨停数量；
- 一字板或换手板；
- 首封时间、开板和回封次数；

- 近 5/10 日累计涨幅；
- 龙头高度、板块涨停数量和晋级率；
- 中位股、后排和昨日连板反馈；
- 高位负反馈和情绪拥挤；
- 利好定价程度；
- 无先手资金的可执行性。

连板数量不是唯一的机械剔除条件，但一字涨停不可成交、高位期望为负、预期回撤过高或无先手不可执行时，必须阻止进入普通买入池。

### 6.8 基本面与财务因子

- 营收、净利润、扣非净利润及增速；

- 毛利率、净利率、ROE、ROIC；
- 经营现金流和自由现金流；
- 应收账款、存货和合同负债；
- 资产负债率、有息负债和商誉；

- 订单和产能；
- 盈利预测上调或下调；

### 6.9 估值与拥挤因子

- 市值、流通市值和自由流通盘；
- 机构持仓、融资余额和股东户数变化；
- 分析师预期拥挤度；
- 价格隐含的乐观预期；
- 事件和利好定价程度。

周期行业需结合商品价格、库存、产能和盈利周期，禁止只用静态 PE。

### 6.10 事件与新闻因子

### 6.11 公司治理与风险因子

### 6.12 持仓与组合因子

- 持仓成本、浮盈亏、持有时间；
- 最大浮盈、盈利回撤和止损距离；
- 原始逻辑存续度；

- 组合拥挤度和流动性。

## 7. 重大事件引擎

事件引擎分为三层：

1. 原始事件层：保存来源事件 ID、原文/原始载荷、URL、`published_at`、`first_seen_at`、`received_at`、`corrected_at`、`retracted_at` 和内容哈希；
2. 规范事件层：保存不可覆盖的 canonical event 版本、聚类关系、分类器版本、实体映射和置信度；
3. 触发层：事件与重算 outbox 在同一事务写入，worker 通过幂等键至少一次消费，支持重试、死信、优先级和 30 至 60 秒合并窗口。

现有公告只有日期、标题和链接，且当前全量任务晚于 18:30；在接入交易所/公司/监管一级来源并保存精确首次可见时间和正文前，“实时重大公告”只能标为规划能力。现有新闻快讯可用于提醒和前向采样，但不能替代一级公告源。

### 7.1 事件范围

事件引擎覆盖：

- 全球战争、制裁、停火、航运和供应链；
- 国内外货币、财政和监管政策；
- 商品价格和产业供需突变；
- 行业政策、涨价、技术突破、订单和招标；
- 公司财报、业绩预告、重组、减持、解禁、诉讼和事故。

### 7.2 来源等级

| 等级 | 来源 | 决策权限 |
|---|---|---|
| 一级 | 交易所、公司公告、政府、央行、统计部门 | 可直接触发重算 |
| 二级 | 权威财经媒体、行业协会 | 可触发预警和重算 |
| 三级 | 券商研报、专业产业媒体 | 需交叉验证 |
| 四级 | 自媒体、社交平台、未经证实传闻 | 仅进入线索池 |

转载不得重复累计权重。同一事件需聚类去重，并保留所有来源。

### 7.3 事件有效影响

`direction`、`severity`、`credibility`、`freshness`、`surprise`、`entity_relevance` 和“已定价代理”是独立事件特征，不采用未经统计标定的直接连乘公式。

- 不同事件类别分别做事件研究，标签采用相对行业/市场的 1/3/5 日异常收益和下行风险；
- `surprise` 只有在存在决策时点的一致预期快照时才允许计算，否则为缺失；
- “未定价程度”使用事件发生至决策时的异常收益、成交和拥挤度相对同类历史反应分位等可复算代理，不由语言模型主观填写；
- 重大监管、立案、财务证伪等可以进入规则风险门禁；
- 正面事件只有在该事件类别通过独立样本外验证后，才可影响 `ACTIONABLE`；
- 战争、突发政策等稀有事件样本不足时，只能触发风险重估或观察，不宣称存在已校准收益概率；
- 语言模型只负责分类、实体映射候选和解释，不能独立触发交易。

利好已经被连续涨停、成交拥挤或估值扩张充分反映时，应提高兑现和回撤风险，而不是继续重复奖励利好。

### 7.4 事件传播图

事件必须映射至：

```text
事件 → 宏观变量 → 行业 → 上下游 → 公司 → 当前持仓
```

同一事件允许同时产生直接受益、间接受益、成本受损和不确定四类关系，禁止对整个大类行业一刀切。

### 7.5 事件衰减

- 盘中传闻：小时级；
- 普通公告：1 至 5 个交易日；
- 行业涨价：按价格和库存周期更新；
- 产业政策：按落地阶段更新；
- 制度性变化：中长期保留并持续验证。

衰减参数按事件类别在训练窗口或事件研究中确定。转载热度、新闻数量和媒体重复不得被当成独立事件样本。

## 8. 市场状态概率模型

市场先输出可观察状态向量：风险偏好、上涨宽度、收益集中度、波动压力、成交额变化、拥挤度和恶化速度。现有 V3 手写 logit/softmax 结果只作为 `HEURISTIC_PRIOR`，在滚动 OOS 校准前不得称为实证概率。

所有概率字段必须携带 `probability_kind`：

- `HEURISTIC_PRIOR`：启发式先验，只能辅助解释；
- `EMPIRICALLY_CALIBRATED`：历史频率校准；
- `MODEL_PREDICTED`：独立样本外模型预测并完成校准。

市场至少研究以下前瞻事件：

- `attack_probability`：全面进攻；
- `rotation_probability`：结构轮动；
- `risk_rising_probability`：风险上升；
- `panic_probability`：恐慌；
- `recovery_probability`：修复。

这些事件允许同时发生，按独立二元事件建模，不要求概率之和为 1。若未来改为互斥多分类，必须更换字段和模型契约，禁止两种语义混用。

同时输出：

- 风险资产总仓位上限；
- 单行业仓位上限；
- 高波动资产仓位上限；
- 允许的新增风险预算；
- 市场状态置信度和主要证据。

状态切换采用概率、持续性和滞回机制。单次脉冲不得直接导致组合全仓反转。

## 9. 行业阶段与轮动模型

行业和概念题材分别建模；一个股票可属于多个题材，题材状态不互斥。每个行业或题材先维护六类“当前可观察状态分”：

1. 低关注积累；
2. 启动；
3. 扩散；
4. 拥挤；
5. 分歧；
6. 退潮。

“低关注积累”完全由当前成交占比、相对强度、拥挤度和资金代理定义，不因未来上涨而事后标记。状态分只有在未来转移频率完成独立校准后，才可升级为阶段概率。

行业模型另行预测：

- `P(未来3/5日相对跑赢)`；
- `P(未来3/5日上涨宽度扩张)`；
- `P(未来3/5日发生退潮回撤)`；
- `P(从当前观察状态转入下一状态)`。

阶段状态机必须冻结转移条件、最短持续期、解除条件和滞回阈值。现有题材“资金加速”若由成交额推导，只能称成交额加速，不能展示为净流入。

### 9.1 行业轮动证据

行业退出证据：

- 相对收益拐头；
- 成交占比高位回落；
- 资金连续流出；
- 龙头放量滞涨或破位；
- 中后排快速走弱；
- 利好不再推动上涨；
- 高位负反馈扩散。

行业接力证据：

- 相对收益从低位转正；
- 成交占比温和提升；
- 资金连续流入；
- 上涨宽度扩大；
- 龙头和中军同步走强；
- 催化尚未充分定价；
- 估值和拥挤度仍可接受。

### 9.2 预警级别

- 黄色：停止新增；
- 橙色：降低原方向仓位，建立替代方向观察仓；
- 红色：主逻辑破坏，退出大部分仓位；
- 轮动确认：替代方向通过价格、资金和扩散验证，允许增配。

## 10. 个股前瞻预测模型

### 10.1 预测目标

每个预测必须先绑定不可变 `ForecastContract`，至少包含：

```text
forecast_key
decision_clock
signal_at
feature_cutoff_at
earliest_order_at
entry_order_policy
entry_fill_model
fill_probability_model
earliest_exit_at
holding_sessions
exit_policy_id
cost_model_id
benchmark_id
target_rule
protection_rule
tradability_rule_id
label_mature_at
```

盘后、盘前和盘中预测不得共用含义模糊的同一标签。至少拆成：

1. `FORECAST_ONLY_NEXT_SESSION`：预测下一交易日市场表现，只用于“明天可能怎样”，不直接代表可买；
2. `ACTIONABLE_ENTRY_VALUE`：从真实可执行成交价开始，计入成交概率、T+1、费用、滑点和退出规则的买入价值；
3. `HOLDING_VALUE`：针对已有持仓，从当前时点到下一可执行退出时点的继续持有价值。

每只股票在相应契约下至少输出：

- 次日净收益大于 0 的概率；
- 未来 3 日净收益大于 0 的概率；
- 目标位先于保护位触发的概率；
- 未来 1/3 日最大回撤超过阈值的概率；
- 预期净收益；
- 预期最大回撤；
- 风险收益比；
- 预测置信度和有效期限。

### 10.2 标签与成交规则

- “1 日/3 日”均指交易日，并明确是否包含入场日；
- 新买入股票的入场日只记录 MAE/MFE，不能模拟止损卖出；最早退出日为下一交易日；
- 一字涨停未成交不静默删除，需单独估计或记录 `P(fill)`；
- 同一日同时触及目标和保护位时，只有分钟/逐笔数据才能判断顺序；仅有日 K 时使用保守顺序或标记 `AMBIGUOUS`，不得选择有利结果；
- 涨跌停制度按股票、板块、ST 状态、上市阶段和历史日期确定，不使用统一 10%；
- 停牌、退市整理、缺失行情和右删失样本分别标记；
- 换仓先模拟卖出腿，卖出失败时不得假设释放资金；
- 所有净收益包含与生产一致的佣金、最低佣金、印花税、过户费、滑点、冲击成本和未成交机会成本。

### 10.3 模型路线

第一阶段使用可解释模型：

- 逻辑回归；
- 梯度提升树；
- 概率校准；
- 特征贡献解释；
- 按市场状态和行业阶段分层校准。

复杂模型只有在样本外显著优于简单基线时才允许上线。

训练、校准和最终测试按交易日整体切分。对重叠持有期标签执行 purge 和 embargo，禁止随机拆分同日股票。先做全局校准，只有状态分层拥有足够独立交易日和事件数时才允许分层校准，否则回退全局或使用层级收缩。

`prediction_confidence` 不等于预测概率，必须综合数据质量、校准支持度、模型分歧、样本覆盖和分布漂移。

### 10.4 候选分层

| 状态 | 含义 |
|---|---|
| `RESEARCH` | 有研究价值，无执行资格 |
| `WATCH` | 进入观察，等待条件 |
| `CONDITIONAL` | 明确盘中触发条件 |
| `ACTIONABLE` | 数据、概率、风控和执行条件均通过 |
| `HOLD_ONLY` | 仅适用于已有先手持仓 |
| `EXIT_ALERT` | 持仓需减仓或退出 |
| `BLOCKED` | 硬风险或不可执行 |
| `INSUFFICIENT_DATA` | 数据不足 |

热点、涨停和高连板股票默认不得因热度直接进入 `ACTIONABLE`。

## 11. 统一持仓重估

所有已有持仓和新候选进入同一比较框架。

### 11.1 持仓逻辑存续度

```text
thesis_survival
= market_support
 + sector_support
 + price_structure
 + capital_confirmation
 + event_validity
 + fundamental_validity
 - crowding_risk
 - breakdown_risk
```

### 11.2 继续持有效用

```text
action_utility
= E[R_net]
 - λ × CVaR95(loss)
 - non_fill_expected_loss
 - untradeable_gap_expected_loss
 - uncertainty_margin
```

上式所有项必须采用同一持有期和同一收益率量纲。`E[R_net]` 已是无条件期望，不得再次乘上涨概率。若模型分别估计条件收益，则完整计算为 `P(up)×E[gain|up] + P(down)×E[loss|down]`。

持仓成本、浮亏和历史最大浮盈不能作为继续持有价值的正向预测理由，避免把“舍不得止损”编码进模型；它们只用于费用、税务、可卖数量、盈利保护和风险预算。

### 11.3 换仓优势

```text
replacement_edge
= U(换仓后的组合)
 - U(保持当前组合)
```

组合效用已包含买卖两腿的费用、冲击、未成交、T+1、行业集中和预测不确定性。普通换仓只有在 `replacement_edge` 的保守置信下界大于 0 且持续至少两个有效快照时允许；重大事实风险可以绕过持续性要求。阈值、持续时长和冷却期必须由历史及模拟盘验证确定，不得人工随意降低。

## 12. 动态退出体系

### 12.1 立即风险退出

- 重大利空或监管风险；
- 财务和业绩事实被证伪；
- 经券商或独立行情确认的真实价格异常波动；
- 跌停和流动性风险快速扩大；
- 原始买入事实失效。

数据源冲突、行情过期或报价不可验证时进入 `DATA_FEED_FAIL`，停止新增并切换可信源，不自动卖出。

### 12.2 行业退潮退出

- 行业由扩散进入分歧或退潮；
- 龙头连续负反馈；
- 资金持续流出；
- 持仓弱于行业和市场；
- 替代行业形成确认。

### 12.3 个股结构退出

- 放量滞涨；
- 突破失败；
- 跌破关键结构且无法快速收回；
- 资金流与价格背离；
- 利好兑现无承接；
- 最新预期收益转负。

### 12.4 机会成本退出

当前股票不一定大跌，只要替代机会在扣除费用和误差后明显更优，就允许分步换仓。

### 12.5 执行动作

动作统一为：

- `HOLD`：继续持有；
- `REDUCE_25`：减仓 25%；
- `REDUCE_50`：减仓 50%；
- `EXIT`：清仓；
- `ROTATE`：退出并换入替代标的；
- `LOCKED_T1`：应退出但受 T+1 限制；
- `UNSELLABLE`：跌停或停牌无法成交。

每个动作必须同时输出：

```text
desired_action
executable_action
blocked_reason
earliest_execution_time
sellable_quantity
locked_quantity
```

“应该卖”与“当前能卖”严格分离。不可卖持仓仍占用现金和风险预算，不得在组合优化中被视为已经释放资金。

## 13. 组合构建与风险预算

组合目标：

```text
maximize
  expected_portfolio_return
  - drawdown_penalty
  - volatility_penalty
  - sector_concentration_penalty
  - crowding_penalty
  - turnover_cost
```

必须约束：

- 单股仓位；
- 单行业及高相关行业合并仓位；
- 高风险情绪交易仓位；
- 总仓位和现金；
- 日换手上限；
- 流动性和冲击成本；
- T+1 锁定；
- 市场状态对应的风险预算；
- 组合回撤降档机制。

输出当前仓位、目标仓位、差值、动作、原因、触发条件和失效条件。

每条预警包含：

- 预警级别；
- 发生时间；
- 影响范围；
- 事实证据；
- 当前判断；

### 15.2 建议接口

```text
GET  /api/v4/dashboard/compact?run_uid=...
GET  /api/v4/decision-context/{run_uid}
GET  /api/v4/market-state?run_uid=...
GET  /api/v4/sector-states?run_uid=...&cursor=...
GET  /api/v4/rotation-alerts?run_uid=...&cursor=...
```

所有 POST：

- 强制鉴权、`Idempotency-Key`、并发互斥和限流；

AI 聊天接口只能解释上述结构化结果。没有有效 `decision_id` 和数据快照时，不得独立生成股票买入推荐。

## 16. 数据库设计

### 16.1 直接复用的现有账本

| 能力 | 现有所有者 |
|---|---|
| 账户、交易意图、订单、成交、费用、现金、持仓 lot、T+1、行情事件 | V2 `st_trade_*_v2`、`st_order_v2`、`st_fill_v2`、`st_position_lot_v2` 等 |
| 决策运行、预测、目标组合、仓位状态、假设和证据 | V3 `st_decision_run_v3`、`st_alpha_forecast_v3`、`st_target_portfolio_v3`、`st_position_state_v3`、`st_trade_hypothesis_v3` |
| 模型注册、验证、反事实和前向成交证据 | V3 `st_model_registry_v3`、`st_validation_result_v3`、`st_counterfactual_v3`、`st_forward_trade_evidence_v3` |
| 不可变数据源快照/清单 | V2 `st_data_snapshot_v2`，按需扩展 manifest |

V4 不新建第二套订单、成交、现金或持仓账本，也不直接写 fill、lot 和 cash ledger。

`st_decision_run_v3` 采用 expand migration 增加可空的 `context_id`、`parent_run_uid`、`trigger_type` 和发布状态语义；不新建重复的 `st_decision_run_v4`。账户级重估和动作存入带 `account_id` 的 V4 投影表，一个全局市场 run 可以服务多个账户，但账户结果不得互相复用。

### 16.2 首期必要新增表

| 表 | 粒度与用途 |
|---|---|
| `st_decision_context_v4` | 每个 `context_id` 一行，不可变上下文及 source manifest hash |
| `st_source_watermark_v4` | 每个 context × source 一行，保存事件/接收时间、覆盖率和延迟 |
| `st_factor_definition_v4` | 每个因子版本一行，保存角色、可用性和 PIT 资格 |
| `st_entity_feature_snapshot_v4` | 每个 run × scope type × entity × feature set 一行向量及哈希，不按单因子逐行 |
| `st_sector_state_v4` | 每个 run × 行业/题材一行，保存观察状态和预测字段 |
| `st_rotation_alert_v4` | 每次不可变轮动预警/状态转移一行 |
| `st_event_raw_v4` | 每个来源事件版本一行，保存原始时间、载荷和哈希 |
| `st_event_v4` | 每个 canonical event 版本一行，不覆盖历史版本 |
| `st_event_entity_link_v4` | 每个事件版本 × 实体 × 影响关系一行 |
| `st_event_recalc_outbox_v4` | 每个事件版本 × 重算范围一行，可靠触发 worker |
| `st_position_revaluation_v4` | 每个 run × account × position 一行 |
| `st_replacement_candidate_v4` | 每个 run × account × current position × alternative 一行 |
| `st_decision_action_v4` | advisory action；不是订单表 |
| `st_alert_transition_v4` / `st_alert_state_v4` | 不可变状态变化 / 当前状态投影 |
| `st_paper_intent_outbox_v4` | 已提交动作向 V2 模拟执行链的可靠 outbox |
| `st_job_run_v4` | job attempt、lease、输入水位、耗时和错误 |
| `st_decision_channel_head_v4` | 按模式/账户原子指向最新 `COMMITTED` run |

### 16.3 数据契约

所有账户级结果必须带 `account_id`。时间存 UTC `DATETIME(6)`，展示转换为 Asia/Shanghai，并区分来源发生、公开、首次看到、接收、计算和可用时间。

写入流程：

```text
RUNNING
→ 按 run_uid 分批写入结果
→ 校验行数、哈希、来源水位和质量
→ COMMITTED
→ 原子切换 channel head
```

查询只读取 `COMMITTED`。所有表需在迁移中明确主键、唯一幂等键、查询索引、外键逻辑、数据所有者、保留期和归档策略。

高频全市场因子不按“每个因子一行”落 MySQL。MySQL 只保留决策实际使用的向量、持仓、Top 候选和审计摘要；原始/高频历史按日压缩归档，热数据保留期由容量测试确定。现有约 30GB 分钟 K 必须通过预聚合读取，禁止运行时反复全表扫描。

### 16.4 现有数据表整改前置项

- 为全市场按时间读取的分钟资金表增加经过在线迁移评估的时间优先索引；
- 公告事件只读取 `association_validated=1` 的关联，并按 `art_code`/来源事件 ID 聚类，禁止把同一公告的多股票关联或转载当成多条独立新闻；
- 五档盘口从“覆盖式当前表”改为可选 append-only 采样后，相关因子才可从 `BLOCKED` 晋级；
- 行业归属增加 `effective_from/effective_to` 或不可变快照；无法还原的旧日期标记 `REPLAY_INELIGIBLE`；
- 盘中状态表区分 current projection 与 append-only transition/history；
- 高频特征读取使用增量聚合表或内存状态，不直接对原始分钟表做高频窗口扫描；
- 所有 DDL 从业务运行路径移到 `migrations_v4.py`，大表索引采用预检查、维护窗口或在线方案。

### 16.5 主键、幂等与查询索引约定

- `st_decision_context_v4`：主键 `context_id`；唯一键 `context_hash`；按 `decision_at` 查询；
- `st_source_watermark_v4`：主键/唯一键 `(context_id, source_name)`；按 `(source_name, received_at)` 查询；
- `st_factor_definition_v4`：主键 `(factor_key, feature_set_version)`；按 `availability_status` 查询；
- `st_entity_feature_snapshot_v4`：唯一键 `(run_uid, scope_type, scope_id, feature_set_version)`；按 `(scope_type, scope_id, computed_at)` 查询；
- `st_sector_state_v4`：唯一键 `(run_uid, scope_type, scope_id)`；按 `(run_uid, state_score)` 和 `(scope_id, computed_at)` 查询；
- `st_event_raw_v4`：唯一键 `(source, source_event_id, content_hash)`；按 `first_seen_at`、`received_at` 查询；
- `st_event_v4`：唯一键 `(canonical_event_id, event_version)`；历史版本不可更新覆盖；
- `st_event_entity_link_v4`：唯一键 `(canonical_event_id, event_version, entity_type, entity_id, impact_type)`；
- `st_event_recalc_outbox_v4`：唯一幂等键 `(canonical_event_id, event_version, scope_hash, worker_version)`；按 `(status, priority, available_at)` 消费；
- `st_position_revaluation_v4`：唯一键 `(run_uid, account_id, stock_code)`；
- `st_replacement_candidate_v4`：唯一键 `(run_uid, account_id, current_stock_code, alternative_stock_code)`；
- `st_decision_action_v4`：主键 `action_id`；唯一键 `(run_uid, account_id, stock_code, action_type)`；
- `st_paper_intent_outbox_v4`：唯一键 `action_id`，确保一个动作只物化一次；
- `st_alert_transition_v4`：唯一键 `(alert_id, transition_no)`；`st_alert_state_v4` 主键 `alert_id`；
- `st_job_run_v4`：主键 `job_id`；唯一键 `idempotency_key`；按 `(status, lease_expires_at)` 查询；
- `st_decision_channel_head_v4`：主键 `(channel, account_id, mode)`，更新时校验目标 run 已 `COMMITTED`。

实际 DDL 还需明确字段长度、非空、枚举约束、JSON schema 版本和预计行数。所有唯一键必须有重复提交测试，所有高频查询必须在生产规模 `EXPLAIN` 和压测通过后合并。

## 18. 实施阶段

### 阶段 0：冻结旧口径

- 标记当前推荐结果为研究或模拟用途；
- 禁止 AI 将旧高分榜描述为确定买入；

- 所有输出显示数据时间。

### 阶段 2：历史留存和事件账本

- 建立 append-only 盘中轻量采样、事件原始层、规范层和重算 outbox；

### 阶段 4：个股概率预测

- 建立 forecast-only、actionable-entry 和 holding-value 三类模型；
- 完成训练/校准/最终测试隔离、purge/embargo、样本外校准和解释；
- 候选分层并隔离不可执行标的。

### 阶段 5：持仓重估、退出和换仓

- 统一持仓与候选效用；
- 建立立即风险、行业退潮、结构破坏和机会成本退出；
- 加入 T+1 和换仓滞回。

### 阶段 6：组合、页面和通知

- 目标仓位优化；
- 五张清单和事件影响展示；
- 预警升级与解除；
- AI 解释接口接入。

### 阶段 7：持仓盘中热路径

- 先上线持仓、活动订单和 T+1 锁定仓的常驻风险 worker；
- 通过断线、陈旧数据、重复事件、DB 超时、重启和时钟偏差故障演练；
- 容量实测通过后，逐步扩展到行业和 200 至 500 只短名单；
- 全市场高频重模型不在首期范围。

### 阶段 8：历史回放和模拟盘

- 无泄漏逐日和盘中回放；
- 20 个交易日仅用于运行稳定性 burn-in，不授予模型有效性 PASS；
- 前向量化验收至少 120 个交易日且至少 80 笔成熟组合交易；
- 未通过验收不得接入真实自动下单。

## 20. 验收指标

### 20.1 数据与审计

- 关键决策数据时间完整率 100%；
- 未来数据泄漏为 0；
- 每条动作可追溯至因子和事件；
- 数据 `FAIL` 时新增买入数量为 0。

### 20.2 预测质量

- Brier Skill、Log-loss Skill、ECE/ICI、校准斜率和截距优于或不劣于冻结基线；
- 高概率组实际胜率应单调高于低概率组；
- 不同市场状态均报告独立表现；
- 报告置信区间，不只报告平均值。
- 下行稀有事件另报 PR-AUC；
- 置信区间按交易日块自助法计算，不按股票逐行抽样；
- 至少比较无条件、市场/行业、简单动量和固定持有基线；
- 校准必须在与生产相同的候选过滤和可成交样本上评估。

### 20.3 风险和轮动

- 大幅回撤必须在协议中预先定义期限、绝对/波动调整阈值；在此基础上计算预警召回率；
- 预警平均提前时间；
- 错误预警率；
- 行业退潮信号后的回撤控制；
- 相比固定持有基准的最大回撤改善；
- 换仓后扣费超额收益；
- 日均换手和交易成本可控。

### 20.4 交易表现

- 扣除真实费用后的净收益；
- 净期望大于 0、Profit Factor 不低于 1.30、Payoff Ratio 不低于 1.00；
- 最大回撤不高于 12%；
- 单笔和组合尾部损失；
- 与指数、固定持有、简单行业动量基准比较；
- 至少 4/5 个冻结外层窗口为正；
- 累计候选搜索的多重检验通过；现有 77 次搜索必须进入统一控制，不能只统计单次活动；
- 执行 1.5 倍/2 倍成本、延迟一日、删除最佳 5 笔、TopN、参数、资金规模和成交参与率压力测试；
- 20 个交易日运行稳定性 burn-in；
- 至少 120 个交易日且至少 80 笔成熟组合交易的冻结前向表现。

收益不作为唯一上线条件；数据正确、无泄漏、风险可控和决策可解释是强制条件。

任何模型、因子、阈值、TopN、成交规则、成本规则或退出协议发生实质调整，相应前向计时和样本重新累计。短期回撤低、单个案例命中或工程测试通过均不能替代量化 PASS。

### 20.5 运行性能与可靠性 SLO

以下为首期目标，部署前需通过生产同规格压测确认：

- 持仓报价年龄 p95 不超过 15 秒；超过 30 秒停止新增并进入保护模式；
- 全市场轻量快照覆盖率不低于 95%，年龄不超过 75 秒；
- 持仓风险计算 p95 不超过 2 秒；
- 行业温路径端到端不超过 180 秒；
- 200 至 500 只短名单重排不超过 60 秒；
- 已验证一级重大事件入库到持仓重估 p95 不超过 60 秒；
- compact API p95 不超过 500ms；
- 任务运行超过自身周期时合并下一轮，禁止无限排队；
- stale 数据下新增买入数量为 0，重复 action/intent 数量为 0。

## 21. 2026 年 6 月科技轮动场景回归

专项回放需逐交易日回答：

1. 科技行业拥挤度何时开始升高；
2. 相对收益、成交占比和资金何时出现恶化；
3. 龙头和中后排何时开始背离；
4. 系统何时发出停止新增、减仓和退出提醒；

6. 替代方向何时获得价格、资金和扩散确认；
7. 每次动作在当时有哪些已知证据；
8. 若系统没有发出预警，缺失的是数据、特征、模型还是阈值。

目标不是事后要求某一天精准清仓，而是检查系统在已知数据约束下能否逐日还原证据、避免迟到引用和违反风险规则。由于该案例已经用于提出需求，它不得参与模型选择或阈值调优，也不得作为统计上线证明。题材成分可靠快照始于 2026-07-24 左右，无法还原的 6 月题材归属必须明确标为 `REPLAY_INELIGIBLE`，可用行业级或当时已归档证据进行有限诊断，不得用当前成分倒灌。

## 22. 爱丽家居场景回归

专项回放必须验证：

- 连续涨停数和累计涨幅是否正确；
- 收购是否仍为意向性事件；

## 23. 上线与回滚

上线顺序：

1. 影子运行，不影响 V3；
2. 页面只读展示；
3. V4 模拟盘；
4. V3/V4 并行对照；
5. 验收通过后将 V4 设为默认解释口径；
6. 真实交易仍需单独授权。

每次发布必须保存：

- 代码版本；
- 配置版本；
- 模型与校准版本；
- 数据迁移版本；
- 基准回放结果；
- 回滚脚本和回滚条件。

回滚按层处理：

- 数据/运行故障：自动关闭新增动作并降为只读，不因数据错误自动卖出；
- 模型异常：冻结新买入，切换上一稳定模型指针，不自动修改历史数据库；
- 应用异常：把默认读取 channel 从 V4 切回 V3；
- 模拟交易：取消未物化 outbox 和允许取消的未成交意图，已成交订单不得自动反向；
- Schema：只使用 expand/contract 前向迁移，不自动执行 destructive down migration；
- 证据：失败运行、原始事件和审计记录全部保留。

MySQL DDL 可能隐式提交，迁移必须具有预检查、逐步 checkpoint、幂等恢复、备份和恢复演练，不能假设一个事务能原子回滚全部 DDL。

若发生数据失真、预测方向失效、换手异常、预警风暴或模拟盘超出风险阈值，系统首先自动降级为只读监控，再按上述层级由稳定指针回退。

上线前必须完成 QMT 断线、数据陈旧、事件重复/撤回、DB 超时、worker 重启、时钟偏差、迁移中断和队列积压故障演练。影子运行资源开销不得影响 V3。

## 24. 完成定义

V4 只有同时满足以下条件才算完成：

1. 所有决策使用统一、可追溯的数据快照；
2. 重大事件能实时影响市场、行业、个股和持仓；
3. 行业轮动和退潮具有概率、证据和预警等级；
4. 个股输出经过样本外校准的前瞻概率；
5. 持仓不受原始策略标签束缚，能够动态减仓和退出；
6. 当前持仓和替代标的进入统一效用比较；
7. 五张清单及失效条件完整展示；
8. 历史回放无未来数据泄漏；
9. 2026 年 6 月科技轮动和爱丽家居场景回归通过，但不将其当作模型有效性证明；
10. 20 日运行稳定性、120 日且 80 笔成熟交易的前向门槛以及 OOS/多重检验均通过；
11. 未经单独授权，不提交真实自动订单。

工程能力可以按阶段分别标记完成；在第 10 项完成前，产品整体状态仍为 `PAPER_ONLY/BLOCKED_FOR_ACTIONABLE`，不得因页面、接口或模拟成交链路完成而宣称交易模型上线。

## 25. 最终决策口径

V4 的最终问题不是“这只股票属于什么策略”，而是：

> 截至当前时点，基于已经确认的市场、行业、价格、资金、基本面和事件事实，继续持有或现在买入这只股票，是否仍具有相对于风险、交易成本和替代机会的正期望？

如果答案发生变化，系统必须改变动作，而不是维护过去的标签或观点。
