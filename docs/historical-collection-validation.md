# 历史行情采集与完整分区复用

日线复用只回放完成凭证声明的 `gj_big_qmt_inner` 原生分区，并继续核对精确股票集合、记录数、质量状态和权限状态。相同交易日其他来源的历史行保留，不混入该原生凭证。凭证要求的股票被覆盖为其他来源时仍须失败，不能缩小目标集合冒充完整。

2026-07-13 的现有日线包含 5,523 条有完成凭证的 QMT 行及 78 条来源为空的旧行。把全部 5,601 行套入原生凭证会误报分区不一致；正确复用无需再次下载，也无需删除旧行。

分钟采集引用已验证的原生日线无交易证明时，日线事实保留自己的不可变股票目录和交易日历根。分钟采集可以使用后来发布的目录和日历，两组权威记录分别从数据库回放。日线证明内部的根、日期、提供方和证明哈希仍须一致，采集时点不得变造，实际日线或分钟记录与无交易证明冲突时仍阻断。

分钟子进程的覆盖校验失败以结构化 `DATA_BLOCKED` 和退出码 3 返回。父进程沿用现有分类规则，不把数据完整性问题误判为登录失效；连接故障继续走终端恢复路径。

影响范围为 Windows 行情采集及两端共享的覆盖凭证验证，按跨端部署。无数据库结构、桥接协议或任务归属变更。历史分区只有在原生采集、正式入库及独立读库校验完成后才算修复，不能直接改缺口台账为成功。

历史日线的 `qmt-daily-no-row-exceptions.v1/v2/v3` 与原生 `qmt-daily-native-no-trade.v1` 含义不同。前者包含上市、退市及经核对的数据不可用例外，不能投射成分钟无交易事实，也不能计为原生停牌。涉及目标日例外的旧日线凭证保留，采集入口通过正常原生全日采集重新取得完整数据和原生无交易证明。分钟数据确有缺口时，先复核该日原生日线依赖；依赖不完整就先采集并独立验收日线，然后采集分钟。已经完整的分钟分区继续直接复用，不触发依赖采集。

2024 年起的批量历史任务，在每个待补日线或分钟分区开始前检查本机 MySQL 实际数据目录所在磁盘，保留 10 GiB 可用空间。不足或无法核实本地存储时立即结束本轮，保留已经完成的数据和进度；不能继续遍历下载后才发现生产磁盘写满。完整分区的只读复核与复用不受该下载门槛影响。

完整分钟复用与发布使用同一字段边界：QMT 原生响应允许缺省均价，保留 NULL 并可复用；提供了非正数或非有限均价时仍拒绝。缺少必需行情字段、来源不明、分钟集合不完整同样不能复用。

覆盖证明经过校验后仍返回完整的 `manifest_hash` 和 `manifest_json`，使正式分钟回执和后续独立回放消费同一份完整证明。不能在首次校验时丢弃原始 JSON，导致后续把有效覆盖误判为缺少证明。分钟发布在撤销旧回执和写入目标表之前，先用实际暂存行数检验最终回执所需的完整时间网格证据。

分钟回读按覆盖凭证声明的股票集合核验，集合内所有记录必须属于凭证对应的 QMT 采集批次。历史表中的 B 股等集合外数据保留，不纳入 A 股覆盖计数；集合内来源或批次被覆盖、记录缺失，以及原生无交易股票出现分钟行，仍须失败。2026-07-08 实测 A 股原生分区为 1,329,838 行，另有 37 只 B 股的 8,880 条旧记录，不能把两者混成同一覆盖分区。

历史补数、缺口执行、夜间扫描和补数计划的运行账号连接统一使用 `create_pooled_engine`，应用已有的强制 TLS 和 CA 校验。不能直接调用 SQLAlchemy 创建不带 TLS 的运行连接，否则生产账号会在采集前返回 1045。Windows 既有私有 option file 的分离读写身份和受验证连接保持原有边界。该修复同时涉及 Windows 补数与 Linux 扫描、计划入口，按跨端发布；不改账号、权限、数据库结构或采集数据契约。
