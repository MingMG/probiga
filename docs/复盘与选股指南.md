# 更细的复盘框架 + 如何用库里的表「选票」

本文建立在：数据已落入 MySQL **`probiga`**（`si_*` / `sm_*` / `st_*`）的前提下。复盘是**理解与叙述**，选股是**在叙述上加规则筛票**；两者都**不构成投资建议**。

---

## 一、复盘可以拆成哪几层（由粗到细）

### 1. 定锚：时间与是否交易日

- 用 **`si_trade_calendar`**：`trade_status = 1` 的日期才是「交易日 T」。
- 所有日级表尽量统一用 **`trade_date = T`**（或 `T` 所在周的区间做周线复盘时再扩）。

### 2. 宏观：指数与波动

| 问题 | 可看的表 | 看什么 |
|------|----------|--------|
| 大盘涨跌、位置 | `sm_index_kline` | 多根 K 的 `close`、`change_pct`、是否放量（`volume`/`amount`） |
| 当日分时结构 | `sm_index_minute` | 开盘半小时、午盘、尾盘斜率与量能 |
| 最新环境（若你有快照任务） | `sm_index_current` | 与上一收盘对比的情绪 |

**复盘问题示例**：T 日是「单边上涨 / 震荡 / 冲高回落」？与过去 5～20 根日 K 比是突破还是假突破？

### 3. 中观：板块与资金结构

| 问题 | 可看的表 | 看什么 |
|------|----------|--------|
| 哪条主线在动 | `sm_concept_east_kline` / `sm_concept_ths_kline` | 概念指数涨幅、是否连续强 |
| 资金是否跟进 | `sm_concept_capital_flow_east` | 板块主力净流入是否为正、是否放大 |
| 情绪榜（若已同步） | `st_hot_concept_ths_rt`、`st_hot_concept_ths_daily` | 热度与涨幅是否一致 |

**复盘问题示例**：涨幅靠前的是「大板块」还是「小题材」？资金是**集中**在少数概念还是**发散**？

### 4. 微观：个股与行为金融

| 问题 | 可看的表 | 看什么 |
|------|----------|--------|
| 位置与趋势 | `sm_stock_kline` | `change_pct`、`turnover_ratio`、高低点 |
| 日内博弈 | `sm_stock_minute`、`sm_stock_bar` | 分时是否均价上方运行、尾盘是否抢筹/砸盘 |
| 主力态度 | `sm_stock_capital_flow_daily`、`sm_stock_capital_flow_min` | 日级 `main_net_inflow` 与价格是否同向 |
| 事件驱动 | `st_a_list_daily`、`st_a_list_info` | 上榜原因、席位净买/净卖 |
| 风险标签 | `st_mine_clearance_tdx` | 高分/高风险项是否集中 |

### 5. 边际变量（偏中线或次日准备）

- **北向**：`st_north_flow_daily`（T 日净流入与结构）。
- **两融**：`st_securities_margin`（余额变化方向）。
- **解禁**：`st_stock_lifting_last_month`（近窗是否压到持仓票）。

### 6. 收盘后「写一句结论」

用一句话回答：**指数环境 → 主线板块 → 自己持仓/自选是否在主线上 → 有无事件（龙虎榜/解禁/北向）需要次日应对**。这就是可执行的「复盘笔记」骨架。

## 二、选股：在复盘结论上「加规则」

选股 = 把「你认为重要的因子」写成 **SQL 条件** 或 **脚本参数**。下面是与当前库表**直接对应**的常见因子（可组合）。

| 因子类型 | 典型条件（思路） | 主要表 |
|----------|------------------|--------|
| 事件 | T 日出现在龙虎榜 | `st_a_list_daily` |
| 资金 | T 日主力净流入 > 阈值 | `sm_stock_capital_flow_daily` |
| 动能 | T 日涨幅、换手区间 | `sm_stock_kline`（注意 `k_type` / `adjust_type` 与同步时一致） |
| 题材 | 属于某 `concept_code` | `si_stock_concept_east` |
| 排除 | 扫雷评分过高、ST 等 | `st_mine_clearance_tdx`、`si_all_code` 简称规则等 |

**组合示例（逻辑，非完整 SQL）**：

1. **「龙虎榜 + 主力净流入为正」**：`st_a_list_daily` ∩ `sm_stock_capital_flow_daily` on `(stock_code, trade_date)`。  
2. **「强势概念里的成分股 + 当日换手」**：`si_stock_concept_east` 过滤概念 → 与 `sm_stock_kline` 在 T 日 join。  
3. **次日观察池**：只做 **LHB 净买为正且席位里机构席偏多**（需 `st_a_list_info` 解析 `operate_name` 关键词，规则需你自己定义）。

## 三、工具：命令行初选股票

仓库提供脚本（从库读数、 stdout 打印表格，可选 CSV）：

```text
python tools\screen_stocks.py --list
python tools\screen_stocks.py --date 2024-07-12 --mode lhb --top 30
python tools\screen_stocks.py --date 2024-07-12 --mode flow --min-main-flow 10000000 --top 50
python tools\screen_stocks.py --date 2024-07-12 --mode k_day --min-change 5 --max-change 11 --min-turnover 3 --top 40
python tools\screen_stocks.py --mode concept --concept-code BKxxxx --top 100
python tools\screen_stocks.py --mode hot_ths_daily --date 2024-07-12 --top 20
```

**低位启动 / 趋势 / 连板（需已同步 `sm_stock_kline` 日 K）：**

```text
python tools\screen_stocks.py --date 2024-07-12 --mode low_start --top 40
python tools\screen_stocks.py --date 2024-07-12 --mode trend --top 40
python tools\screen_stocks.py --date 2024-07-12 --mode ladder --min-boards 2 --max-boards 4 --top 40
```

含义简述：

| 模式 | 规则直觉 | 可调参数（见 `python tools\screen_stocks.py -h`） |
|------|-----------|-----------------------------------------------------|
| `low_start` | 前 N 日（默认 60）**不含当日**的窗口内最低价；当日收盘离低点不远（默认 ≤28%）；当日**温和上涨**（默认约 2%～10.5%）；成交量 ≥ 前 20 日均量（不含当日）的倍数（默认 1.25） | `--low-lookback`、`--max-from-low`、`--start-min-chg`、`--start-max-chg`、`--vol-boost` |
| `trend` | 当日 **MA5 > MA10 > MA20** 且 **收盘在 MA5 之上**（经典多头排列）；可按 `--trend-min-chg` 要求收阳等 | `--trend-min-chg` |
| `ladder` | 以 **`change_pct ≥ --limit-pct`** 近似「涨停日」；用窗口数**连续涨停日**得到连板数；只保留板数在 **`--min-boards`～`--max-boards`**（默认 2～4，偏「非首板、非过高」） | 主板默认 `--limit-pct 9.8`；**创业板约 19.5**；**ST 约 4.9** |

说明：连板与涨停阈值在 A 股因板块、是否注册制、是否 ST 而异，**脚本无法替你自动识别**，请按标的类型改 `--limit-pct`。规则仅为量化近似，**不等于**交易所涨停判定。

### 日 K 筛选 + 公告 + 舆论（库内 + 东财公告接口）

当前 **`probiga` 里没有「全文公告库」**（巨潮/交易所 PDF 落库需另做同步）。脚本用两层方式补「公告」：

1. **库内「舆论/行为」代理**：`--with-context` 会在含 `stock_code` 的结果上 **LEFT JOIN**  
   - **`sm_stock_capital_flow_daily`**：`ctx_main_net_inflow`（当日主力净流）  
   - **`st_a_list_daily`**：`ctx_lhb_reason` / `ctx_lhb_net_amount`（是否上榜、原因）  
   - **`st_mine_clearance_tdx`**：`ctx_mine_max_score`（扫雷最高分，表内为最近一次同步快照，**非按日历史**）  
2. **公告**：列 **`ctx_eastmoney_notice_url`** 指向东财个股公告列表页；若加 **`--fetch-notices N`**（需 **`httpx`**，见 `requirements-platform.txt`），会再请求东财 JSON **最近 N 条标题**写入 `ctx_recent_notice_titles`（仅对前 40 只股票请求，并带 `--notice-sleep` 间隔，避免封 IP）。

示例（先筛日 K 形态，再带上下文）：

```text
python tools\screen_stocks.py --date 2024-07-12 --mode low_start --top 25 --with-context
python tools\screen_stocks.py --date 2024-07-12 --mode trend --top 25 --with-context --fetch-notices 3
```

`--mode concept` 且未设 `--date` 时，资金流/龙虎榜对齐日请用 **`--context-date 2024-07-12`**。

**舆论**若还要更广（热股榜、热门概念、北向等），请用 **`--mode hot_rank_ths` / `hot_ths_daily`** 单独看板块与榜单；与个股日 K 的 **人工对照** 即可形成完整叙事。

**公告标题入库（可与 `--with-context` 联动）**：先同步表 **`si_notice_eastmoney`**：

```text
python -m biz.notice.sync_notice_em --stock 600519 --max-pages 5
python -m biz.notice.sync_notice_em --from-si-all-code --offset 0 --limit 100 --max-pages 2 --sleep 0.35
```

同步后，`screen_stocks.py --with-context` 会多合并 **`ctx_notice_cnt_30d` / `ctx_last_notice_date`**（以 `--context-date` 或 `--date` 为截止的近 30 个自然日窗口）。公告 **PDF 正文** 仍建议用 **`ctx_eastmoney_notice_url`** 或 **`detail_url`** 在浏览器打开；若需巨潮全文归档，可再扩展同步任务。

环境变量与其它脚本一致：**`MYSQL_URL`**；K 线筛选默认 **`k_type=1`、`adjust_type=1`**，若你同步时改过 `SM_STOCK_K_TYPE` / `SM_STOCK_ADJUST_TYPE`，请用脚本参数 **`--k-type` / `--adjust-type`** 对齐。

## 四、重要说明

1. **数据是历史快照**：`sm_stock_current` 等是某次抓取时刻的快照，不适合当「长期收盘价」做严肃回测，除非你有连续归档策略。  
2. **选股结果是候选池**：仍需人工看图形、公告、流动性；表结构不保证覆盖全部业务字段。  
3. **合规**：本仓库工具仅作数据整理与本地研究，不构成投资建议。

若你希望下一步做成 **固定「复盘一页 HTML」** 或 **FastAPI 只读查询接口**，可以说明偏好的输出形态（浏览器 / Excel / API）。
